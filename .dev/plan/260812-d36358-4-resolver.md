# 회차 4 — `addResolver` 한 줄 + 리뷰 잔여

## A. `addResolver(Applicative, ...)` — 회차 3의 미완

회차 3이 `Maybe.Monoid` 선례를 따르면서 **지연 해석기만 빼먹었다**(규칙 25 가 여기서 나왔다).

```
Monoid.of('maybe(first)')      — 팩토리 호출 전에도 OK   ← addResolver(Monoid, ...) 덕분
Applicative.of('const(array)') — 팩토리 호출 전  THROW   ← 없다
```

`index.js:1498` 의 선례와 같은 모양으로:

```javascript no-run 변경안
addResolver(Applicative, key => {
    const m = /^const\((.+)\)$/.exec(key);
    return m ? Applicative.Const(m[1]) : null;
});
```

**놓을 위치**: `Applicative.Const` 정의(`index.js:1028`) 뒤 어디든. 다만 기존 두 resolver 가
`index.js:1491-1501` 에 **모여 있으므로** 그 옆에 둔다 — 다음 사람이 "resolver 는 여기" 로
찾을 수 있어야 한다.

**주의**: `Applicative.Const` 는 1028줄, resolver 는 1491줄. `addResolver` 는 `key =>` 클로저
안에서 부르므로 호출 시점 참조라 순서 문제 없다(기존 `Monoid` resolver 가 `Maybe.Monoid` 를
같은 방식으로 부른다).

테스트: **팩토리를 부르지 않은 상태에서** `Applicative.of('const(array)')` 가 되는지.
지금 테스트는 `Applicative.Const('array')` 를 먼저 부르므로 이 구멍을 못 잡는다 —
**별도 프로세스에서 확인해야 한다**(테스트 파일 안에서는 앞 테스트가 이미 등록해버린다).
