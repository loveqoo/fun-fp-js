# Free 동시성 후보 — fan-out/fan-in·fiber (착수 미정, 가능성 기록)

2026-08-29 소유자 대화에서 나온 가능성 기록입니다. **지금 하자는 것이 아닙니다** —
소유자가 "가능성만 언급"이라고 못 박았고, 착수는 소유자의 명시 지시가 있을 때만 합니다.
구현 계획이 아니라, 나중에 꺼낼 때 대화를 다시 하지 않아도 되게 하는 서랍입니다.

## 소유자 판정 (2026-08-29)

- Free 모나드는 CPS 방식으로 일반 라이브러리가 하기 힘든 것을 할 수 있다.
- 병렬 실행(fan-out) 후 race(1)만 취할 수도, 모두(all)를 취할 수도 있다. fan-in 구현도
  쉽게 가능하다.
- EffectTS 의 fiber 도 구현할 수 있을 것이다.
- **Task 기능과 별개다** — Task 를 고치는 게 아니라 Free 어휘·해석기 차원의 확장이다.

## 왜 구조가 허용하는가 (대화에서 합의한 이치)

- Free 의 `chain` 사슬은 본질상 순차다(다음 걸음이 앞 걸음의 결과를 먹는다). 병렬은
  사슬을 비트는 게 아니라 **어휘에 명령을 더하는 방식**이 된다: "이 프로그램 여럿을
  동시에 돌려라"라는 명령의 짐칸에 하위 Free 프로그램들을 싣고, 해석기가 자기 러너를
  재귀로 불러 각각 돌린 뒤 race 든 all 이든 해석기가 합친다. 러너는 이미 프로미스 기반.
- race(1)은 race(k)로 일반화된다 — "m 개 중 먼저 끝난 k 개"는 프로미스가 기본으로 안
  주는 조합인데, 어휘로 만들면 명령 하나다.
- fiber 는 "따로 도는 해석 루프 + 손잡이(join·interrupt)"다. 걸음 단위 trampoline 러너가
  그 밑판이고, interrupt 는 걸음 사이에 보는 취소 신호다. JS 단일 스레드이므로 이벤트
  루프 위의 협조적 동시성이 된다(EffectTS 도 같은 처지).

## 본 공사가 어디인지 (쉬운 절반과 어려운 절반)

- **쉬운 절반** — fork/join, race/all 의 값 얻기. 어휘 명령 + 해석기 재귀 호출.
- **어려운 절반** —
  - race 에서 **진 가지의 취소**: 안 끊으면 진 가지가 자원을 붙든다. `start` 협조적
    취소와 맞물릴 자리. 취소 시점의 뒷정리(열어 둔 것 닫기) 보장까지 가면 EffectTS 의
    interruption 안전성 급의 공사다.
  - fiber 의 **감독(structured concurrency)**: 부모가 죽으면 자식도 정리되는 보장.
    fork/join 자체보다 이쪽이 본 공사다.
  - **Actor 와의 역할 경계**: 이미 있는 동시성 원시(Actor)와 fiber 의 자리를 먼저
    그어야 한다.

## 이 라이브러리다운 매력 한 가지

어휘로 만든 동시성은 **시험이 결정적**이 된다 — race 가 명령이면 시험 해석기가 "2번이
먼저 끝난 셈 치라"고 순서를 각본대로 정할 수 있어, 동시성 테스트의 고질적 흔들림이
구조적으로 사라진다. fan-out 자체보다 이쪽이 차별점이라는 데 에이전트 의견을 적어 둔다.

## 형태 — 별도 라이브러리 (소유자 방향, 2026-08-29)

같은 날 대화가 이어져 형태까지 그어졌다. **본체가 아니라 fun-fp-js 에 의존하는 별도
라이브러리**로 만들 수 있다(소유자: "별도의 라이브러리로 만들어야 할 수도").

- **근거 1 — 런타임 의존성**: fiber·race 의 실익은 이벤트 루프에 비동기 대기가 있는
  런타임(Node·브라우저)에서만 나온다. GAS 는 모든 I/O 가 블로킹이고 setTimeout 이 없어
  겹칠 대기 자체가 없다(이 판정은 문서 근거 추정, GAS 실측은 안 함). 런타임 타는 기능을
  본체에 넣으면 "의존성 0·26KB·런타임 중립"이라는 본체 약속이 흐려진다.
- **근거 2 — freeze 와 같은 방향**: 본체는 닫고 확장은 밖에서. 6차 freeze 권고(⏸)와 일치.
- **덤 — API 충분성의 시험대**: 확장이 공개 API(Free.api·해석기 조립·start)만으로
  지어지는지가 문이 제대로 나 있는지의 증명이 된다. 안 지어지면 본체에 낼 문이 정확히
  드러난다 — 그때가 freeze 조건 여섯과 대조할 시점.
- **착수 전 확인 1건**: 진 가지 취소에는 걸음 수준 제어(걸음 사이 끼어들기·취소 신호
  주입)가 필요한데, 지금 공개 문이 그 수준까지 여는지 실측 필요(확인 안 함).
  - **본체를 직접 고치게 되는 순간 소유자에게 알린다** (2026-09-02, 소유자가 이 약속의
    위치를 물어 여기 명시). "거기"는 `index.js` `/* Free */` 의 `Free.api` 쪽 `start`
    구현(`makeApiStart`, 취소 토큰·걸음 사이 검사)이다. 소스 읽기만으로는: 토큰은 사설이고
    공개 손잡이는 `start` 가 돌려주는 `cancel` 뿐, 검사는 핸들러 비행이 끝난 뒤와 연속의
    매 걸음 사이. 그러므로 진 가지에 `cancel()` 을 쏘는 것까지는 공개 문으로 될 듯하나,
    **비행 중인 핸들러(열린 fetch 등)를 끊는 것**은 안 닿는다 — 문을 내야 한다면 그 자리.
    실행·실측은 안 함.
- **시기**: 별도 패키지는 본체 버전을 따라다닌다. 0.x 는 공개 API 가 흔들릴 수 있는
  시기이므로, 자연스러운 순서는 본체 1.0 뒤.
- **GAS 별론**: GAS 에서 Free 가 빛날 자리는 동시성이 아니라 6분 실행 제한을 넘는
  장기 실행의 분할·재개(명령 기록 + replay) 쪽 — 이것도 추정, 확인 안 함.

## 표현의 계단 — 제너레이터 → Free 값 → AST (2026-08-29 문답)

같은 날 대화가 표현 방식의 스펙트럼까지 갔다. 셋 다 "걸음 단위로 제어권을 내놓는
협조적 스케줄러"라는 밑판은 같고, 프로그램을 얼마나 값으로 만드느냐가 다르다.

| 단계 | 값인 부분 | 얻는 것 | 치르는 것 |
| --- | --- | --- | --- |
| 제너레이터 함수(공장) | 공장 자체(불투명한 값) | 문법 공짜(if·for·try/finally), 빠름, 재실행·재해석 됨(공장 재호출) | 중간 지점을 값으로 못 쥠(갈래는 replay, O(N)+결정성 규율), 대수·법칙 게이트에 못 낌 |
| Free 값 (현 본체) | 지나온 등뼈 | 재해석·중간 공유 O(1), Functor/Monad 대수·레지스트리·법칙 게이트 | chain 속 함수는 불투명(전체 정적 분석·직렬화 불가), chain 계단, 해석기 오버헤드 |
| AST (몸통까지 자료) | 전부 | 전체 정적 검사, 직렬화 → GAS 6분 재개가 replay 없이 성립, 결정성이 구조가 됨 | 작은 언어를 소유(If·While·변수 마디, 유효 범위·에러 메시지), 표현력↓ |

- **소유자 통찰 1** — 제너레이터 인스턴스는 일회용이지만 공장은 값이다. Effect.gen 이
  정확히 이 방식(값 뼈대 + 제너레이터 표기법). 별도 라이브러리를 짓는 날의 유력한 그림.
- **소유자 통찰 2** — 몸통을 AST 로 만들면 불투명성이 걷힌다. 선례는 AWS Step
  Functions(워크플로 = JSON AST — 검증·시각화·중단·재개·감사), 반대편 Azure Durable
  Functions 는 replay 방식(규율을 사용자에게 지움). 이 문단은 기억 기반, 재검색 안 함.
- **근본 다이얼** — AST 가 할 수 있는 게 많아질수록 AST 에 대해 알 수 있는 게 준다.
  임의 함수까지 넣으면 JS 해석기 재발명이 되어 불투명성이 언어 안쪽에서 되살아난다.
  절제의 방법은 이 저장소의 레지스트리 원칙 그대로 — 임의 계산은 이름으로 명부에,
  자료에는 열쇠만. AST 화는 그 원칙을 제어 흐름까지 확장하는 일이다.
- **자리 판정** — 시험 가능한 효과 분리까지면 지금 Free 로 충분. GAS 재개·감사 가능
  워크플로가 목표가 되는 날 AST 계단이 값을 한다.
