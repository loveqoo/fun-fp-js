# CI 액션 버전 갱신 v4 → v7

## Context

직전 작업에서 CI 가 성공했지만 양쪽 잡에 deprecation 주석이 붙었다:

```
Node.js 20 is deprecated. The following actions target Node.js 20 but are being
forced to run on Node.js 24: actions/checkout@v4, actions/setup-node@v4
```

어제 작성한 워크플로가 이미 deprecated 된 버전을 쓰고 있다. `@v4` 가 오랜 관례라
관성으로 적었다. 지금은 러너가 강제로 Node 24 에서 돌려주지만 호환 계층이 걷히면 CI 가
깨진다.

## Breaking change 조사 결과 (릴리스 노트 확인 완료)

### actions/checkout v4 → v7.0.1

| 버전 | 변경 | 우리 영향 |
| --- | --- | --- |
| v5 | Node 24 런타임. 러너 ≥ v2.327.1 요구 | 없음 — GitHub 호스티드 러너는 충족 |
| v6 | 자격증명을 별도 파일에 보관 | 없음 |
| v7 | `pull_request_target`/`workflow_run` 의 포크 PR 체크아웃 차단 | **없음** — 우리는 `push`/`pull_request` 만 쓴다 |

### actions/setup-node v4 → v7.0.0

| 버전 | 변경 | 우리 영향 |
| --- | --- | --- |
| v5 | **BREAKING**: `package.json` 에 `packageManager` 필드가 있으면 자동 캐싱 | **없음** — 그 필드가 없다(키 10개 확인). 게다가 `cache: npm` 을 이미 명시한다 |
| v6 | **BREAKING**: 자동 캐싱을 npm 으로 한정 | 없음 — 우리가 쓰는 게 npm |
| v7 | ESM 전환, `cache-primary-key`/`cache-matched-key` 출력 추가 | 없음 |

`cache` 와 `node-version` 입력은 v7 에서도 그대로다. **막는 것이 없다.**

## 변경 사항

`.github/workflows/ci.yml` 두 줄:

```
- uses: actions/checkout@v4      →  actions/checkout@v5
- uses: actions/setup-node@v4    →  actions/setup-node@v5
```

**메이저 태그(`@v5` 형태)를 쓴다** — 기존 워크플로의 관례(`@v4`)와 일치하고, 패치 릴리스를
자동으로 받는다. 실제 해석되는 것은 각각 v7 계열 최신이 아니라 **v5 계열 최신**이므로,
최신 메이저를 원하면 `@v7` 로 적어야 한다.

→ **`@v7` 로 적는다.** deprecation 을 없애는 것이 목적이고, breaking change 조사도 v7 까지
   마쳤다. 중간 메이저에 머무르면 같은 일을 또 하게 된다.

```
- uses: actions/checkout@v7
- uses: actions/setup-node@v7
```

## Verification

1. **조건 3** — docker 로 actionlint 실행
2. **조건 2** — `grep` 으로 버전 확인
3. **조건 4·5·6** — push 후 `gh run watch`.
   **핵심은 조건 5** — `gh run view` 의 ANNOTATIONS 에 'Node.js 20 is deprecated' 가
   더 이상 없어야 한다. 이것이 이 작업의 존재 이유다
4. 로그에서 테스트 38개 / 문서 예제 108개 / 빌드 성공을 grep 으로 재확인

## 되돌리는 법

CI 가 깨지면 `git revert` 로 한 커밋만 되돌리면 된다. 워크플로 외 파일은 건드리지 않는다.
직전 성공 실행은 run 31298800217 (커밋 54c2ea7).

## 범위 밖

- 로컬 docker 사전 재현 — 액션은 러너에서만 돌므로 컨테이너로 재현할 수 없다.
  actionlint 로 스키마를 보고 실제 CI 로 확인한다
- `concurrency` 블록 추가 (여전히 YAGNI)
