# Optics — Iso 추가

## Context

profunctor 인코딩으로 전환한 직후다. 그 전환의 부수 효과로 **`Iso` 가 거의 공짜가 됐다** —
직전 작업의 프로토타입에서 이미 동작을 확인했다.

## 설계

```js
const Iso = (to, from) => P => pab => P.dimap(to, from, pab);
```

**`dimap` 만 쓴다.** 세 P(함수·Forget·Tagged)가 전부 `dimap` 을 가지므로 **모든 연산이
동작한다** — `Iso` 는 Lens 이자 Prism 이다.

| 연산 | Iso 에서 | 왜 |
| --- | --- | --- |
| `view(iso, s)` | `to(s)` | Forget.dimap 이 `s => p(to(s))`, p 는 항등 |
| `review(iso, a)` | `from(a)` | Tagged.dimap 이 `g(p)` = `from(a)` |
| `over(iso, f, s)` | `from(f(to(s)))` | 함수.dimap |
| `preview` / `toListOf` | 항상 1개 | Forget |

**이것이 optic 계층에서 Iso 가 최상단인 이유다** — 요구하는 것이 가장 적으니 가장 많은 곳에
쓰인다.

### 법칙

```
from(to(s)) === s      // round-trip 1
to(from(a)) === a      // round-trip 2
```

무손실 변환이라는 뜻이다. 이 둘이 깨지면 Iso 가 아니다.

### 뒤집기는 따로 만들지 않는다

`reverseIso` 는 기존 연산으로 유도된다 — `Iso(a => review(iso, a), s => view(iso, s))`.
전용 함수를 넣을지는 이번 범위 밖. 문서에 유도 방법만 적는다.

   (Lens 이자 Prism 이라는 증거)

   `composeOptic(each, iso)` 세 조합
4. **조건 8** — 구현 깨뜨리기: `dimap` 의 `to`/`from` 순서를 뒤집으면 잡히는가
5. `npm test` + `tsc` + 문서 예제 + CI

## 되돌리는 법

`Iso` 는 기존 코드에 손대지 않고 **추가만** 한다. 커밋 하나를 revert 하면 끝이다.

## 범위 밖

- `reverseIso` — 기존 연산으로 유도되므로 문서에 방법만 적는다
- `Optional`, `Fold`, `Getter`/`Setter`
- TS 브랜드로 optic 종류를 컴파일 타임에 구분하는 것
