# docs/ 신규 기능 7종 문서 + 예제 실행 검사기

## Context

`docs/` 에는 타입 클래스와 기본 데이터 타입 문서 30종이 있지만, 이후에 추가된 기능 7종
(Lens, Actor, Transducer, StateT, EitherT, ReaderT, WriterT)은 문서가 없다. 코드와 타입
선언과 테스트는 있는데 **읽고 배울 곳이 없다.**

동시에 이 저장소는 직전 두 작업에서 "검증되지 않는 것은 썩는다" 를 두 번 확인했다
(실행되지 않던 테스트 파일, 실행되지 않던 문서 명령어). 문서 2,800줄을 검증 없이 추가하면
같은 일이 세 번째로 반복된다. **그래서 문서보다 검사기를 먼저 만든다.**

목표: 7종 문서가 기존 30종과 같은 템플릿·깊이로 존재하고, 그 예제가 `npm test` 와 CI 에서
**실제로 실행되어** 코드와 어긋나면 빨간색이 된다.

## 회차 분할

이 작업은 한 회차에 끝나지 않는다. 완료 조건 8개는 전 회차에 걸쳐 유지된다.

| 회차 | 범위 |
| --- | --- |
| **1 (지금)** | 검사기 + Lens.md, Transducer.md, Actor.md — 서로 독립적인 3종 |
| 2 | StateT.md, EitherT.md, ReaderT.md, WriterT.md — 공통 인프라를 공유하는 4종 |
| 2 말 | `docs/README.md` 인덱스 편입 + Node 20/22 컨테이너 검증 |

검사기를 먼저 만드는 이유: 문서를 쓰는 동안 예제가 계속 검증되어야 한다. 나중에 붙이면
2,800줄을 다 쓴 뒤에 고치게 된다.

## 변경 사항

### 1. `tests/docs-examples.test.js` (신규) — 이번 회차의 핵심

파일명이 `*.test.js` 라서 **`tests/run.js` 가 자동으로 집어간다.** 러너도 CI 도 수정 불필요.

- **allowlist**: 7종 파일명을 상수로 박는다. 아직 없는 파일은 **"(아직 없음)" 으로 출력**하고
  넘어간다 — 회차 1에서 4종이 없는 것은 정상이고, 조용히 넘기지 않는다.
- **추출**: ` ```javascript ` 블록은 실행 대상, ` ```javascript no-run ` 은 스킵 대상.
  스킵 개수를 문서별로 출력한다(조용한 누락 금지).
- **실행**: 블록마다 독립 프로세스.
  `spawnSync(process.execPath, ['--input-type=module', '-e', preamble + code])`
  preamble 은 `import FunFP from '<index.js 의 file:// URL>';`
- **보고**: `tests/utils.js` 의 `test()` 를 쓴다 → ✅/❌ 출력과 `process.exitCode = 1` 을
  공짜로 얻고, 다른 테스트 파일과 형식이 같아진다. 실패 시 블록의 stderr 를 그대로 보여준다.
- 문서별 요약: `docs/Lens.md — 12 run, 2 skipped`.

### 2. `docs/Lens.md`, `docs/Transducer.md`, `docs/Actor.md` (신규)

`docs/` 는 사람 소유 폴더다 — 사용자가 이 작업을 명시적으로 승인했고,
Execution 에서 `harness allow "docs/*"` 로 예외를 등록한다.

기존 데이터 타입 문서 템플릿을 따른다:

```
# 이름
(한 줄 요약)
## 개념
## 왜 X인가?     ← 문제(```javascript no-run) → 해결(실행 가능)
## 생성
## 주요 연산     ← 연산별 ### 소제목, 각각 실행 가능한 예제
## 타입 체크
## 실용적 예시   ← ### 1. ~ ### 4. 번호 매김
## 관련 타입 클래스
```

각 200줄 이상, 실용적 예시 3개 이상. 예제는 `tests/` 의 검증된 코드에서 파생시킨다.

**주제별 초점**:
- **Lens** — 불변 중첩 업데이트. Lens 법칙 3개(get-set / set-get / set-set),
  `composeLens` 가 필요한 이유(Van Laarhoven F-explicit 인코딩이라 일반 `compose` 로는
  합성 불가 — `index.js:2262` 주석이 근거).
- **Transducer** — 중간 배열 없는 파이프라인. `map`/`filter`/`take`, 우→좌 합성,
  `take` 의 조기 종료(`Reduced`).
- **Actor** — 순차 메시지 처리. `handle` 이 `[result, newState]` 또는 Task 를 반환,
  `send` 가 Task 를 돌려주므로 비동기 예제는 `fork` 로 끝내지 말고 `no-run` 으로 표시하거나
  최상위에서 완결시킨다.

## Verification

완료 조건 8개 중 이번 회차에서 대조 가능한 것:

1. **조건 5** — `npm test` 출력에 `docs-examples` 파일이 나오고 실행 개수가 보인다
2. **조건 6** — 3종 문서의 실행 가능 예제가 전부 통과하고, **실행 개수가 0이 아님**을
   확인한다 (allowlist 오타로 0개를 실행하고 초록불이 되는 것이 가장 위험한 실패다)
3. **조건 7** — 예제 하나를 일부러 틀리게 고쳐 `npm test` 가 non-zero 인지 확인하고 되돌린다.
   틀리는 방식은 **존재하지 않는 메서드 호출**(`Lens.nope()`)로 한다 — 실제 문서 부패
   시나리오와 같다
4. **조건 2·3** — 각 문서의 섹션 존재와 줄 수를 스크립트로 대조한다(눈으로 세지 않는다)

조건 1·4·8(7종 전부 / README 인덱스 / 컨테이너)은 회차 2에서 대조한다.
