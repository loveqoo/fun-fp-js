조사 방법: 전체 테스트 실행, `tsc --noEmit`, 재빌드 후 dist diff 확인, docs/ 커버리지 대조.

## A. 테스트 게이트 복구 — `npm test` 도입 + 깨진 테스트 수리

**증상**
- `tests/unit-validation.test.js:1` 이 `require('../dist/fun-fp.cjs')` 를 쓰는데
  `package.json` 에 `"type": "module"` 이 있어 `ReferenceError: require is not defined`
  로 즉시 크래시. 37개 테스트 파일 중 1개가 **실행조차 되지 않는 상태**.
- 나머지 36개는 통과. `tsc --noEmit` 도 통과(exit 0).

**근본 원인은 파일 하나가 아니라 러너 부재**
- `CLAUDE.md` 가 안내하는 `for f in tests/*.test.js; do node "$f"; done` 는 실패를
  집계하지 않는다. 개별 파일이 크래시해도 루프의 exit code는 0.
- `package.json` 에 `test` 스크립트가 없다 (`build`, `build:js`, `build:types`,
  `typecheck` 만 존재).
- 그래서 깨진 테스트가 눈에 띄지 않고 남아 있을 수 있었다.

**완료 조건 후보**
- `npm test` 하나로 전 테스트 파일 + `tsc --noEmit` 실행
- 실패가 하나라도 있으면 non-zero exit, 실패한 파일명이 요약으로 출력
- `tests/unit-validation.test.js` 가 ESM으로 정상 실행되어 통과
- `CLAUDE.md` 의 테스트 실행 안내가 새 방식으로 갱신

## B. dist 재현성 — 빌드 타임스탬프 제거

**증상**
- `dist/fun-fp.js`, `.cjs`, `.min.cjs`, `.d.ts` 헤더에 `Built: <ISO timestamp>` 가
  박혀 있다. 소스가 한 글자도 안 바뀌어도 재빌드하면 4개 파일 전부 diff가 난다.
- 실제 확인: 재빌드 후 `git diff --stat dist` 는 4 files / 4 insertions,
  내용은 **전부 타임스탬프 한 줄뿐**.

**왜 문제인가**
- 커밋된 `dist/` 가 현재 소스와 일치하는지 기계적으로 검증할 수 없다.
  `dist` 를 저장소에 커밋하는 구조에서는 이 검증이 유일한 안전장치다.

**완료 조건 후보**
- 타임스탬프 제거(또는 결정적 값으로 대체)
- `node build.js && node build-types.js && git diff --exit-code dist` 가 clean
- `npm test` 또는 별도 스크립트에 dist 동기화 검사 편입
