# docs 정비 — 새 레지스트리 표면 다섯

리뷰어 2차 #6: **새로 공개 레지스트리 시민이 된 다섯 표면이 `docs/` 에 0건.**

```
grep -rn "plus("            docs/  → 0건
grep -rn "Applicative.Const" docs/  → 0건
grep -rn "'identity'"        docs/  → 0건
```

`docs/*.md` 는 예제가 **전부 실행 검사**를 받으므로 **예제가 곧 회귀 테스트**가 된다.
지금 이 다섯은 런타임·타입 선언에만 있고 사용자가 알 길이 없다.

## 쓰기 전에 실행으로 확인했다 (규칙 24 — 근거를 먼저 돌린다)

```
plus(maybe) vs maybe(first)
  같은 타입   Just(1)       vs  Just(1)
  섞인 타입   Just(1)       vs  THROW      ← 갈리는 지점
  null 선두  Just(null)    vs  THROW
  empty      Nothing       (양쪽 같다)

plus(array)   concat([1],[2]) = [1,2]   empty = []   Semigroup 짝도 있다
identity      of(1) = {value:1}   map(x=>x+1,{value:1}) = {value:2}
Const('array') of() = {value:[]}   ap 는 monoid 로 합침   map 은 값을 버림
              Applicative.of('const(array)') === Applicative.Const('array')
```

## A. `docs/Monoid.md` — `plus(<타입>)` 절

`## 사용 예시` 와 `## 실용적 활용` 사이에 넣는다.

내용:
- `Plus` 는 `alt`(결합)와 `zero`(항등원)를 다 가지므로 **구조적으로 Monoid** 다
- 등록된 `Plus` 마다 짝 `Semigroup`/`Monoid` 가 `plus(<alias>)` 로 자동으로 생긴다
- **`maybe(first)` 와의 차이가 핵심** — 위 표를 실행 예제로

## B. `docs/Applicative.md` — `identity` 와 `Const` 절

`## 사용 예시` 뒤에 넣는다.

내용:
- 둘 다 **`traverse` 에 넘기려고** 있는 것이다 — optics 의 `over`/`foldMapOf` 가 쓴다
- `identity` 는 값을 그대로 나른다 → `traverse` 가 "그냥 매핑" 이 된다
- `Const(monoid)` 는 값을 버리고 monoid 로 모은다 → `traverse` 가 "접기" 가 된다
- `Applicative.Const('array')` 와 `Applicative.of('const(array)')` 가 같은 인스턴스

**`Optics.foldMapOf` 와 연결한다** — 사용자가 "이걸 어디 쓰나" 를 묻지 않게.

## C. `docs/Plus.md` — 한 문단

"등록된 `Plus` 는 짝 `Monoid` 를 `plus(<alias>)` 로 얻는다" + `docs/Monoid.md` 링크.

## D. `docs/README.md`

요약 표에 새 키가 보이도록. **학습 순서는 건드리지 않는다** — 새 타입이 아니라 기존
타입의 인스턴스이므로 단계가 늘 이유가 없다.
