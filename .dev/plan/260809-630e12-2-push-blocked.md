# 회차 2 — push 차단으로 실행할 계획이 없다

## 상황

회차 1에서 커밋 5개와 로컬 `main` 머지를 마쳤다. 완료 조건 7개 중 5개 충족.
남은 두 개는 **외부 요인으로 막혀 있다.**

| 조건 | 상태 |
| --- | --- |
| 6. `origin/main` push | ❌ PAT 에 Workflows 권한 없음 |
| 7. GitHub CI 실행 확인 | ❌ push 가 없으니 실행 자체가 없음 |

```
! [remote rejected] main -> main
  (refusing to allow a Personal Access Token to create or update
   workflow `.github/workflows/ci.yml` without `workflow` scope)
```

## 왜 이 회차에 할 일이 없는가

- **코드·설정 문제가 아니다.** 워크플로 YAML 은 actionlint 통과, docker node:20/22 에서
  전체 스텝 실행 통과. 로컬 `npm test` 도 통과한다.
- **대체 경로가 없다.** SSH 키는 로컬에 있으나 GitHub 에 등록돼 있지 않다
  (`Permission denied (publickey)`). `gh auth refresh` 는 토큰이 `GITHUB_TOKEN`
  환경변수로 주입되므로 무력하다.
- **우회는 해악이 크다.** `.github/workflows/ci.yml` 커밋을 히스토리에서 빼면 이력을
  재작성해야 하고, CI 도입이라는 작업 자체가 무의미해진다.

Scaffolding~Verification 에서 새로 만들거나 검증할 것이 없다. 빈 회차를 반복하는 것은
복리가 아니라 마찰이다 (POLICY 9: 진전이 없으면 2회에서 멈추고 사람에게 묻는다).

## 사용자 조치 (이것만 되면 5분이면 끝난다)

https://github.com/settings/personal-access-tokens
→ `github_pat_11AAGYGRI0bAHIGOPV2LWp...`
→ Repository permissions → **Workflows → Read and write** → Save

fine-grained PAT 은 권한만 바꾸면 **토큰 문자열이 그대로**이므로 환경변수 재설정이 필요 없다.

## 조치 후 실행할 절차 (다음 회차)

1. `git push origin main`
2. `gh run watch` — Node 20/22 두 잡이 모두 success 인지 확인
3. 실패하면 로컬 docker 재현과 무엇이 달랐는지 본다 (캐시 키, 러너 환경, 권한)

## 되돌리는 법

로컬은 안전하다. 커밋 5개, working tree 깨끗, `main` 이 `origin/main` 보다 9커밋 앞섬.
되돌리려면 이전 `main` SHA 는 `fa76f7b` 다.

## 이 회차의 결론

**Compounding 으로 건너뛰고 사용자와 다음 행동을 합의한다** — 토큰 수정을 기다릴지,
작업을 일단 닫고 나중에 별도 작업으로 다룰지.
