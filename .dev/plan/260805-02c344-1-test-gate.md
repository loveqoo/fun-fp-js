# 테스트 게이트 복구 — `npm test` 단일 진입점

## Context

이 저장소에는 **작동하는 테스트 게이트가 없다.** 조사 결과 세 가지가 겹쳐 있다.

1. **`CLAUDE.md:25` 의 "전체 테스트" 명령이 실제로는 1개 파일만 실행한다.**
   `node tests/*.test.js` 는 셸이 37개 경로로 확장하지만, node 는 **첫 인자만 실행하고
   나머지는 `process.argv` 로 넘긴다.** 즉 `tests/actor.test.js` 하나만 돌고 끝난다.
2. **`CLAUDE.md:39` 의 셸 루프(`for f in ...; do node "$f"; done`)는 실패를 집계하지 않는다.**
   개별 파일이 크래시해도 루프 자체의 exit code 는 항상 0 이다.
3. **`package.json` 에 `test` 스크립트가 없다** (`build`, `build:js`, `build:types`,
   `typecheck` 만 존재).

그 결과 **`tests/unit-validation.test.js` 288줄이 실행조차 되지 않은 채 방치돼 있었다** —
`require('../dist/fun-fp.cjs')` 를 쓰는데 `package.json` 에 `"type": "module"` 이 있어
`ReferenceError: require is not defined in ES module scope` 로 즉시 크래시한다.
37개 중 이 파일만 CJS 이고, 나머지 36개는 `import fp from '../index.js'` 로 통일돼 있다.

목표: **`npm test` 한 번으로 전체 검증이 돌고, 실패하면 반드시 non-zero 로 끝난다.**

## 이미 확인한 사실 (재조사 불필요)

- `tests/utils.js:57,70` — `test`/`testAsync` 가 실패 시 이미 `process.exitCode = 1` 을
  설정한다. **파일별 exit code 가 이미 신뢰할 수 있다** → utils.js 개조 불필요.
- `tsconfig.json:14` — `include: ["types/**/*.d.ts", "types/**/*.ts"]` 라
  `types/__tests__/*.test-d.ts` 17개가 이미 `tsc --noEmit` 범위 안이다. 현재 exit 0.
- `tests/unit-validation.test.js` 를 ESM 으로 바꾼 사본을 스크래치패드에서 실행해봤다 →
  **23 assertion 전부 통과, exit 0.** 숨은 실패는 없고 전환은 순수 기계적이다.
- `testAsync` 는 이 파일에서 **0회** 사용된다 (`test` 23, `assertEquals` 28,
  `assertThrows` 9).

## 변경 사항

### 1. `tests/run.js` (신규)

`tests/` 디렉터리에 두는 이유: 프로젝트 규칙상 `tests/` 가 "검증에 필요한 모든 파일" 을
소유한다. 파일명이 `*.test.js` 패턴에 걸리지 않으므로 러너가 자기 자신을 실행할 위험도 없다.

동작:

- `fs.readdirSync('tests')` 로 `.test.js` 로 끝나는 파일을 모아 **정렬**한다(실행 순서 결정성).
- 각 파일을 **별도 자식 프로세스**로 실행한다:
  `spawnSync(process.execPath, [file], { stdio: 'inherit' })`.

  **한 프로세스에 몰아서 import 하면 안 된다.** `tests/unit-validation.test.js` 와
  `tests/strictmode.test.js` 가 `fp.setStrictMode(true/false)` 로 **전역 상태를 토글**한다.
  현재의 셸 루프가 우연히 지켜온 프로세스 격리를 러너도 그대로 지켜야 한다.
- 자식의 `status !== 0` 이면 실패로 기록한다. `spawnSync` 가 시그널로 죽은 경우
  (`status === null`, `signal` 있음)도 실패로 센다.
- 테스트를 **전부 돌린 뒤** `tsc --noEmit` 을 실행한다 — 실패해도 중간에 끊지 않는다.
  한 번 실행으로 전체 그림을 보기 위해서다. 실행은
  `spawnSync(process.execPath, [require.resolve 대신 'node_modules/typescript/bin/tsc'], ['--noEmit'])`
  형태로 로컬 typescript 를 직접 호출한다(`npx` 는 네트워크 조회가 끼어들 수 있다).
  로컬 tsc 가 없으면 **에러로 처리**한다 (조용히 건너뛰면 게이트에 구멍이 생긴다).
- 요약을 출력한다:

  ```
  ── Summary ─────────────────────
  test files : 36 passed, 1 failed
  typecheck  : passed
  failed:
    tests/unit-validation.test.js (exit 1)
  ```
- 실패가 하나라도 있으면 `process.exit(1)`, 없으면 `process.exit(0)`.

옵션 플래그(`--only`, `--no-types` 등)는 **넣지 않는다** — YAGNI (`CLAUDE.md:116` 설계 원칙 5).

### 2. `tests/unit-validation.test.js` — ESM 전환

1행과 3행만 교체하고 나머지 285줄은 손대지 않는다.

```js
// before (1행)
const fp = require('../dist/fun-fp.cjs');
// after
import fp from '../index.js';

// before (3행)
const { test, testAsync, assertEquals, assertThrows } = require('./utils.js');
// after — testAsync 는 미사용이므로 뺀다
import { test, assertEquals, assertThrows } from './utils.js';
```

임포트 대상을 `dist/fun-fp.cjs` → `../index.js` 로 바꾸는 것은 단순 문법 수정이 아니라
**의도적인 변경**이다: 나머지 36개 파일의 관례와 일치하고, 테스트가 빌드 산출물이 아니라
소스를 검증하며, `npm test` 전에 빌드를 요구하지 않게 된다.

### 3. `package.json` — scripts

```json
"test": "node tests/run.js"
```

기존 `typecheck` 스크립트는 **유지한다** — 러너가 내부에서 타입체크를 하지만, 타입만
빠르게 보고 싶을 때 여전히 필요하다.

### 4. `CLAUDE.md` — 테스트 실행 섹션 (22~40행)

`node tests/*.test.js` 와 셸 루프 안내를 **삭제**하고 `npm test` 로 교체한다.
개별 파일 실행법(`node tests/maybe.test.js`)은 디버깅에 쓰이므로 남긴다.
잘못된 명령을 지우는 것이 이 변경의 핵심 — 남겨두면 다음 사람이 다시 속는다.

## Verification

Selection 에서 기록한 완료 조건 6개와 1:1 로 대응한다.

1. `npm test` 실행 → 37개 파일 전부 이름이 출력되고 typecheck 줄이 요약에 나온다.
2. `npm test; echo $?` → `0`.
3. **게이트 자체를 시험한다**: `tests/zz-gate-probe.test.js` 에 반드시 실패하는
   assertion 하나를 넣고 `npm test; echo $?` → **`1`** 이어야 하고, 요약의 `failed:`
   목록에 해당 파일명이 나와야 한다. 확인 후 이 파일은 **삭제한다**.
4. `node tests/unit-validation.test.js; echo $?` → `0`, `[FAIL]` 0건.
5. 요약의 `test files` 줄이 `37 passed, 0 failed`.
6. `CLAUDE.md` 22~40행에 `node tests/*.test.js` 와 `for f in` 이 더 이상 없다.

자기검증에 기대지 않도록, 완성된 `tests/run.js` 를 codex 서브에이전트에
**적대적으로 검토**시킨다 (특히: 자식 프로세스 시그널 종료 처리, exit code 전파,
tsc 부재 시 동작).
