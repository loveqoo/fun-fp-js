# 회차 2 — 회차 1의 등록을 철회하고, 진짜 원인인 `'object'` 꼬리표를 고친다

## 무엇이 밝혀졌나

회차 1에서 `MaybeFirst*`/`MaybeLast*` 4개를 등록했다. **그것이 틀렸다.** 조사 결과 두 가지가
나왔고 둘 다 저장소에 기록이 있다.

### ① `first`/`last` 를 Monoid 로 두지 않은 것은 의도다

커밋 `e3d2b82` (2026-01-28, loveqoo):

> First와 Last Semigroup의 경우 **항등원이 존재하지 않아 Monoid 인스턴스를 정의할 수 없으므로**,
> 불필요한 FirstMonoid와 LastMonoid 클래스를 제거함.

지워진 것은 `super(Semigroup.types.FirstSemigroup, () => null, 'object', ...)` 였다 —
`null` 은 `(a,b) => a` 의 항등원이 아니다. `types/data/builtins.d.ts:56-57` 도 같은 말을 한다:
"Monoid default aliases mirror Semigroup **for the combinations that have an identity element**".
`MonoidInstances` 에 `first`/`last` 가 없는 것은 누락이 아니다.

**회차 1의 나는 그것을 8개월 뒤에 되살렸다.**

### ② 그러나 `'object'` 꼬리표는 설계가 아니라 어긋난 것이다

| | 값 |
| --- | --- |
| `types/data/builtins.d.ts` | `readonly first: unknown;` — **모든 타입** |
| `index.js:896` 런타임 | `super(x => x, 'object', ...)` — 숫자·문자열 거부 |

선언과 런타임이 다르다. 최초 도입 커밋(`cb8a467`)에서 `/* Object */` 주석 바로 아래 놓였고,
`(a, b) => a` 는 타입과 무관하므로 **섹션 위치를 따라간 것**으로 읽힌다. 레지스트리 전체에
"아무 타입" 을 뜻하는 값이 없다: `Array, Maybe, boolean, date, function, number, object, string`.

### ③ 그래서 설계가 일관되게 읽힌다 — 그리고 그것이 조립(AST)이다

| | 항등원 | Monoid |
| --- | --- | --- |
| `first` 단독 | 없음 | ❌ `e3d2b82` 로 제거 |
| `maybe(first)` | **`Nothing`** | ✅ |

`index.js:1365-1366` 주석이 그대로 말한다 — "Maybe는 inner가 Semigroup이기만 해도 Monoid를
구성할 수 있다. Nothing이 항등원 역할을 하므로 inner의 empty()가 필요 없다."

**항등원이 `Maybe` 에서 온다.** `maybe(first)` 는 조립이고, 내가 만든 `maybe-first` 는 그 조립을
납작하게 우회한 이름이었다. 실제로 조립은 중첩까지 된다(실행 확인): `maybe(maybe(first))`.

## 변경 사항

### A. `'any'` 타입 도입 (사용자 승인 완료)

```javascript no-run 변경안
// types.check
check: (val, expected) => {
    if (typeof expected !== 'string') return false;
    if (expected === 'any') return true;          // 추가
    const actual = types.of(val);
    return actual === expected || actual.toLowerCase() === expected.toLowerCase();
},
```

`types.equals(a, b)` 검사는 **손대지 않는다** — `first.concat(1, 'a')` 는 계속 거부된다.
`'any'` 는 "이 인스턴스는 값 타입을 안 본다" 는 뜻이지 "아무거나 섞어도 된다" 가 아니다.

### B. `first`/`last` 를 `'any'` 로 정정하고 섹션에서 꺼낸다

```javascript no-run 변경안
super(x => x, 'any', Semigroup.types, 'first');
super((x, y) => y, 'any', Semigroup.types, 'last');
```

`/* Object */` 섹션 **밖**으로 옮긴다 — 그 위치가 `'object'` 를 부른 원인이므로 고쳐도
그대로 두면 다음 사람이 같은 결론을 낸다. 새 주석은 `/* Polymorphic (type-agnostic) */`.

`builtins.d.ts:56` 의 주석줄도 이 위치 이동에 맞춘다. **`SemigroupInstances.first: unknown` 은
그대로 둔다** — 이미 옳다.

### C. 회차 1이 추가한 4개를 삭제한다

`MaybeFirstSemigroup` · `MaybeFirstMonoid` · `MaybeLastSemigroup` · `MaybeLastMonoid`
(`index.js:1131-1154`) 전부 제거. 리뷰 #2(=`MaybeAlt` 중복)와 #5(=키 이름 규약 위반)가
함께 사라진다.

optics 의 모으기 Monoid:

```javascript no-run 변경안
const _firstM = Maybe.Monoid('first');   // Monoid.of('maybe-first') 대신
const _arrayM = Monoid.of('array');      // 유지 — 회차 1에서 이미 옳게 고쳤다
```

**회차 1이 단 주석은 지운다** — "사용자가 바꿔 끼울 수 있다" 는 거짓이었다(리뷰 #4, 실측).
로드 시점 상수 캡처라 레지스트리를 갈아끼워도 안 바뀐다. 실제 입구인 `foldMap` 은 **회차 3**
에서 optics 모듈 객체와 함께 낸다 — 지금 내면 곧 없앨 최상위 bare export 를 하나 더 만든다.

### D. `view` 의 새 동작을 확정한다 (리뷰 #6)

## Verification

1. `Monoid.of('maybe(first)')` 가 아니라 **`Maybe.Monoid('first')`** 로 얻은 인스턴스가
   `Just(1)+Just(2) → Just(1)`, `Just({})+Just({}) → 첫째` 둘 다 되는지 실행
2. `first.concat(1, 'a')` 가 **여전히 거부**되는지 — `'any'` 가 타입 혼합까지 열면 안 된다
3. `grep "maybe-first\|maybe-last\|MaybeFirst\|MaybeLast" index.js` → **0건**
4. `view` 3건 테스트가 **추가 시점에 실패하도록 먼저 쓰고**(현재 동작을 고정하는 것이므로
   통과하겠지만, 에러 메시지 영어화 전에 쓰면 메시지 대조에서 실패한다) 그다음 구현
5. `npm test` — 38 파일 + `tsc --noEmit`. **회차 1과 달리 `view` 3건이 커버되므로 초록이
   의미를 갖는다**
6. `staticland-reviewer` 재검토 → `.dev/review/260811-15c84c-2-*.md`.
   **회차 1의 6건이 각각 어떻게 됐는지 대조를 요구한다**

문제가 생기면 그것만 되돌릴 수 있어야 한다.
