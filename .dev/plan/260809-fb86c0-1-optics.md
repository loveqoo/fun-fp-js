# Optics 확장 — Prism + Traversal

## Context

`index.js` 의 `/* Optics */` 섹션에는 **Lens 하나뿐**이다(31줄). `Prism`, `Iso`, `Traversal`,
`Optional`, `Fold` 는 전부 0건. 합타입의 한 갈래를 다루거나(Prism) 컬렉션 전체를 조작하는
(Traversal) 표준적인 optics 사용법이 불가능하다.

사용자 결정: **Prism(Maybe 매칭) + Traversal(기존 Traversable 재사용)** 까지. `Iso`/`Optional`/
`Fold` 는 이번 범위 밖.

## 설계

### 왜 내부 F 를 확장해야 하는가

현재 `_Identity`/`_Const` 는 `{of, map}` 뿐이다. Lens 는 Functor 면 충분하지만:

- **Prism** — 매칭 실패 시 `F.of(s)` 로 원본을 올려야 한다 (`of` 필요)
- **Traversal** — 0..n 개를 모으려면 `F.ap` 가 필요하다

기존 `ArrayTraversable` 의 traverse 가 `applicative.of / map / ap` 세 가지를 호출하므로
(`index.js:1031`), 내부 F 를 그 형태로 맞추면 **레지스트리의 Traversable 을 그대로 물릴 수
있다.**

```js
const _Identity = {
    of: v => ({ value: v }),
    map: (f, x) => ({ value: f(x.value) }),
    ap: (ff, fa) => ({ value: ff.value(fa.value) }),
};
// Const 는 값을 무시하고 Monoid 로 누적한다 — 어떤 Monoid 를 주느냐가 읽기 방식을 정한다
const _Const = monoid => ({
    of: () => ({ value: monoid.empty() }),
    map: (_, x) => x,
    ap: (a, b) => ({ value: monoid.concat(a.value, b.value) }),
});
```

| 읽기 함수 | Monoid | 결과 |
| --- | --- | --- |
| `view` | 아무거나(Lens 는 map 만 씀) | `a` |
| `preview` | First — `empty=Nothing`, `concat=(a,b)=> a.isJust()? a : b` | `Maybe a` |
| `toListOf` | Array — `empty=[]`, `concat=[...a,...b]` | `[a]` |

### 추가할 것

```js
Prism(match, build)   // match: s -> Maybe a,  build: a -> s
traversed(key)        // 'array' | 'maybe' | 'either' — Traversable.of(key) 재사용
preview(optic, s)     // Maybe a  — 첫 대상
toListOf(optic, s)    // [a]      — 모든 대상
review(prism, a)      // s        — Prism 으로 거꾸로 만들기
composeOptic(...)     // 일반 이름
```

**`review` 는 van Laarhoven 인코딩만으로는 복원할 수 없다** (Choice/Tagged profunctor 가
필요하다). `Prism` 이 돌려주는 함수에 `build` 를 프로퍼티로 붙이고 `review` 가 그것을 읽는다.
Prism 이 아닌 optic 에 `review` 를 쓰면 명확한 TypeError 를 던진다.

### 하위 호환 — 이것이 이 작업의 함정이다

`tests/optics.test.js:131` 이 **에러 메시지를 정확히 단언**한다:
`'composeLens: argument 1 must be a Lens'`. `composeLens` 를 `composeOptic` 의 단순 별칭으로
만들면 메시지가 바뀌어 기존 테스트가 깨진다.

→ 이름과 명사를 매개변수화해 **기존 메시지를 그대로 보존**한다:

```js
const _makeCompose = (name, noun) => (...optics) => {
    optics.forEach((o, i) => {
        typeof o !== 'function' && raise(new TypeError(`${name}: argument ${i} must be ${noun}`));
    });
    return F => compose(...optics.map(o => o(F)));
};
const composeOptic = _makeCompose('composeOptic', 'an optic');
const composeLens  = _makeCompose('composeLens', 'a Lens');
```

`view`/`set`/`over` 의 기존 메시지("lens must be a function")도 건드리지 않는다.

   (조건 4의 핵심: 하위 호환)
2. Prism/Traversal 동작을 테스트로 확인 — 특히 **매칭 실패 시 원본 반환**(조건 6)
3. **혼합 합성** — `composeOptic(lens, traversed('array'), prism)` 같은 조합(조건 5)
4. `npm test` 전체 + `tsc --noEmit`
5. 문서 예제는 검사기가 자동으로 실행한다 — `docs/Optics.md` 를 쓰면 그 즉시 검증된다
6. 부패 주입으로 게이트 재확인, CI Node 20/22

**법칙 테스트를 넣는다.** Prism: `preview(p, review(p, a)) === Just(a)`,
`match 성공 시 review(p, view) === s`. Traversal: `over(t, x => x, s)` 가 원본과 같다.

## 되돌리는 법

`index.js` 의 Optics 섹션만 건드리므로 그 커밋 하나를 revert 하면 된다.
기존 optics 테스트가 하위 호환의 안전망이다.

## 범위 밖

- `Iso`, `Optional`, `Fold`, `Getter`/`Setter`
- 타입 변경(type-changing) optics — 이 라이브러리는 `s -> s` 만 다룬다
- `Traversable` 레지스트리에 새 인스턴스 추가 (array/maybe/either 로 충분)
