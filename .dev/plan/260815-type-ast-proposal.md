# 결정 — AST 는 안 한다. 타입은 두 겹까지다

**한 줄 판정: `.type` 을 타입 AST 로 바꾸는 일은 하지 않는다.** 재귀 구조가 필요 없기
때문이다 — 아래가 그 근거다. 앞선 계획서
[`260814-type-ast.md`](./260814-type-ast.md) 는 이 판정으로 폐기됐다.

**소유자 결정 (2026-08-15)**

> 저의 결정은 자바스크립트의 한계를 인정하는 방향입니다. 이곳은 타입스크립트가 아닙니다.
> 여기서 타입은 기본타입, 클래스 정도 밖에 없습니다. (…) 컨테이너 타입과 값타입, 이렇게
> 두 개만 관리합니다. array에 값이 어떤 타입인지는 우린 모릅니다.
>
> 타입 클래스, 그리고 그 안의 값 타입. 이것이 우리의 한계입니다.
> **`Maybe<Array>` 이지 `Maybe<Array<number>>` 가 아닙니다.**
> 마찬가지로 **`Either<string, Maybe>` 이지 `Either<string, Maybe<number>>` 가 아닙니다.**

이 문서는 그 결정과, 결정에 이르기까지 잰 것들의 기록입니다.

---

## 1. 규칙

```
Type  = 이름 | 이름 '(' 안쪽 (',' 안쪽)* ')'
안쪽  = 이름                    ← 재귀 없음. 여기가 규칙이다.
```

**깊이는 정확히 둘까지.** 안쪽 칸에는 **이름 하나**만 들어갑니다 — 컨테이너 이름
(`Array`·`Maybe`)이든 값 타입 이름(`string`·`number`)이든 상관없지만, **또 다른 적용은
못 들어갑니다.**

관리하는 것은 둘입니다.

| | |
| --- | --- |
| **컨테이너 타입** | `Array` `Maybe` `Either` `Task` `Const` `StateT` `Set` `Map` … |
| **값 타입** | `number` `string` `boolean` `Date` · 클래스 |

JS 가 알려주는 것이 여기까지입니다 — `typeof` · `Array.isArray` · `instanceof` · 클래스.
그 이상은 우리가 지어내는 것입니다.

---

## 2. 왜 두 겹인가 — 세 겹은 표본이지 타입이 아니다

| 캐리어가 지닌 값 | 검사 방법 | 안쪽 칸 |
| --- | --- | --- |
| `Maybe` `Either` `Const` — **1개** | 그 값 하나를 본다. **순회 없음** | 가능 |
| `Array` `Set` `Map` — **N개** | 원소를 순회해야 안다 = **표본** | 불가 |

**표본은 타입이 아닙니다.** 프로토타입으로 직접 확인했습니다 — 재귀 검증을 만들어 돌리니
이렇게 나왔습니다.

```
maybe(number)  에 Nothing()    → 통과
array(number)  에 []           → 통과
task(number)   에 Task.of(1)   → 통과
```

**꺼낼 값이 없으면 무조건 통과합니다.** 빈 배열은 `array(number)` 도 `array(string)` 도 다
통과합니다. 타입이라면 값이 없어도 답이 나와야 하는데 나오지 않습니다. JS 배열이 원소
타입을 지니지 않으니 이것이 한계입니다.

---

## 3. 지금 코드가 이 규칙을 지키고 있나 — 실측

### `.type` 축: 위반 0건

```
서로 다른 instance.type 값: 23종 / 깊이 2 초과: 없음

괄호 있는 것 6종:
  Const(array)   Forget(array)   StateT(Maybe)
  EitherT(Task)  ReaderT(Maybe)  WriterT(Maybe,Array)
```

여섯 다 `바깥(안쪽이름)` 이고 안쪽은 이름 하나입니다. `WriterT(Maybe,Array)` 가 소유자가
든 `Either<string, Maybe>` 와 같은 모양입니다 — 칸이 둘이지만 각 칸은 이름입니다.

### 레지스트리 키: 163종 중 깊이 3 이 하나

`maybe(maybe(array))` 뿐입니다. **그리고 이것은 다른 축입니다.**

```
Semigroup.lookup('maybe(maybe(array))').type   →   'Maybe'      한 겹만 말한다
```

키는 **인스턴스 조립 지시서**이지 타입 선언이 아닙니다. 깊이는 타입 식이 아니라 **위임**이
만듭니다:

```
concat(Just(Just([1])), Just(Just(9)))  → 거부: must match Array    ← 안쪽 인스턴스가 잡았다
concat(Just(Just([1])), Just(9))        → 거부: must match Maybe    ← 가운데 인스턴스가 잡았다
```

**각 인스턴스가 자기 한 겹만 보고, 그것이 이어져 깊이가 납니다.** 소유자 규칙이 이미 이
코드가 작동하는 방식입니다. 그래서 이 키는 **둡니다.**

### 원소 검사는 이미 갈려 있고, 그대로가 맞다

| | 결과 | 왜 |
| --- | --- | --- |
| `Setoid.Array('number').equals([1],['a'])` | 거부 | 안쪽 인스턴스에 **위임**한다 |
| `Semigroup.Maybe('number').concat(Just(1),Just('a'))` | 거부 | 같음 |
| `Functor.lookup('array').map(id,[1,'a'])` | 통과 | `fmap :: (a->b) -> f a -> f b` — `a` 에 제약이 없다 |

`Setoid.Array('number')` 의 `.type` 은 **이미 `'Array'`** 입니다. `array(number)` 는 키일
뿐이고 검사되는 타입이 아닙니다. 규칙대로입니다.

## 4. 폐기한 것 — 이 결정이 죽인 설계

2026-08-14 계획서와 그 뒤 제가 만든 프로토타입에서 다음을 **버립니다.**

| | 왜 |
| --- | --- |
| 재귀 `validate` (44줄) | 세 겹부터는 표본이라 타입이 아니다 |
| `sanctuary-def` 의 `extractors` 차용 | 안쪽을 꺼내 순회한다는 발상 자체가 폐기 |
| `array(maybe(number))` 같은 중첩 타입 | 규칙 위반 |
| 「227곳을 고친다」 | 애초에 틀린 수였다 — 해석 지점은 `types.of`/`check`/`equals` 셋뿐 |

### 남들은 어떻게 했나 — 참고로만 남긴다

`npm pack` 으로 실제 배포본을 받아 읽은 것입니다.

| | 타입의 런타임 표현 | 줄 수(js) |

TypeScript 의 타입을 런타임에 재현하려 하고, 우리는 **JS 가 아는 만큼만** 관리합니다.

## 5. 남은 일 — 컨테이너 축뿐이다

원소가 아니라 **"이 값이 어떤 컨테이너인가"** 를 못 가르는 자리들입니다. 관리하기로 한 둘
중 첫 번째이고, `Array.isArray`·길이·`instanceof` 로 **JS 가 알려주는 범위 안**입니다.

### ✅ 튜플 — 닫힘 (2026-08-15)

```
전:  bimap(x=>x*10, x=>x+1, [1,2,3,4,5])  →  [10, 3]      뒤 셋이 사라졌다
     bimap(x=>x*10, x=>x+1, [])           →  [NaN, NaN]   없는 것을 만들었다
후:  둘 다 거부 — 'Bifunctor.bimap: tuple must have exactly 2 elements, got 5'
```

**`.type` 은 `'Array'` 로 둡니다.** `types.of([1,2])` 가 `'Array'` 를 내므로 `'Tuple'` 로
바꾸면 모든 호출이 실패합니다. JS 가 `[1,2]` 를 배열이라 하는 것을 우리가 못 바꿉니다 —
그것이 「한계를 인정한다」입니다. 대신 **길이를 연산이 봅니다.**

느슨한 모드에서도 삽니다. 느슨한 모드는 **타입** 검사를 끄는 것인데, `[]` 에서
`[NaN, NaN]` 이 나오는 것은 타입 문제가 아니라 결함입니다.

### ☐ `Set` · `Map` · `Triple`

셋 다 **컨테이너 축**이고 JS 가 알려줍니다(`instanceof Set` · `instanceof Map` · 길이 3).
안쪽 칸은 두지 않습니다 — 원소가 여럿이라 표본이 됩니다.

`Map` 은 지금 **표현조차 못 합니다.** 필요해지면 넣습니다.

## 6. 이 결정이 **안 하는 것**

- **위조를 막지 않습니다.** `{ value: 1, _typeName: 'Identity' }` 가 통과합니다.
  `_typeName` 이 JS 모양을 덮는 우선 분기(`index.js:64`)이기 때문이고, 막으려면 **심볼 축을
  값 검사 경로에 끌어들여야** 합니다. 별개 결정입니다.
- **`Functor.map` 의 원소 검사를 만들지 않습니다.** 명세상 만들면 안 됩니다.
- **함수 시그니처 검사를 하지 않습니다.**
- **디스패치를 바꾸지 않습니다.** Static Land 는 인스턴스를 사용자가 고릅니다.
