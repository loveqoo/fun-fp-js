# Optics 문서 재구성 — 이론을 뒤로

## Context

사용자: "optics 문서가 너무 어렵다."

측정해보니 명확했다. **첫 실행 예제까지의 거리**:

| 문서 | 첫 예제 |
| --- | --- |
| `Maybe.md` | 16행 |
| `Either.md` | 18행 |
| `Lens.md` | 52행 |
| `Optics.md` | **68행** |

기존 30종은 20행 안에 코드가 나오는데 내가 쓴 둘은 60행 넘게 이론을 읽힌다.

`## 개념`(5~46행)에 이론 블록이 셋 있다 — 인코딩 공식, Forget/Tagged 표,
first/left/wander 표. **전부 구현 세부다.** 라이브러리를 쓰는 사람은 `P` 를 직접 다루지
않는다. `P` 가 필요한 독자는 `index.js` 를 고치는 사람이고 그쪽엔 이미 `CLAUDE.md` 가 있다.

## 변경 사항

### `docs/Optics.md`

**새 구조** (사용자 결정: 이론은 지우지 않고 맨 뒤로):

```
# Optics
  부제에 Iso 포함           ← 지금 "Lens, Prism, Traversal" 로 빠져 있다
## 어느 것을 쓸까            ← 대상 수 기준 선택 표. 바로 행동 가능
## 빠르게 보기               ← 네 optic 을 한 예제로. 20행 이내 도달
## 왜 optic 인가?            ← 문제/해결. "왜 Prism과 Traversal인가" 는 구현 순서에서 온
                              제목이라 독자 관심사로 바꾼다
## 생성 (Iso/Lens/Prism/Traversal)
## 주요 연산
## 합성
## 법칙
## 실용적 예시
## 내부 구조                 ← 인코딩 공식, P 주입 표, first/left/wander 표를 여기로
## 관련 타입 클래스
## 더 알아보기
```

`## 내부 구조` 는 "왜 `review` 가 Lens 에서 안 되는가" 같은 질문의 답을 담으므로
**지우지 않는다** — 궁금한 사람이 문서를 떠나지 않아도 되게 한다.

### `docs/Lens.md`

개념부의 profunctor 문단을 뺀다. Lens 문서는 "getter/setter 쌍" 까지만 알면 충분하다.
인코딩이 궁금하면 `Optics.md#내부-구조` 로 보낸다.

상단의 안내 인용구도 짧게 — 지금 3줄인데 링크가 셋이라 시작부터 무겁다.

1. **조건 1·3 이 핵심** — `grep -n '^```javascript$' | head -1` 로 첫 예제 행 번호를 재고
   20행 이내인지 확인한다. 눈으로 판단하지 않는다
2. 조건 2 — 이론 블록 셋이 `## 내부 구조` 아래에 있는지 행 번호로 확인
3. 조건 5 — 부제와 선택 표에 Iso 가 있는지 grep
4. **조건 7** — 문서를 재배치하면 예제 순서가 바뀌므로 검사기가 전부 다시 돌아야 한다.
   `docs/Optics.md — N run` 의 N 이 줄지 않았는지 확인(예제를 잃지 않았다는 뜻)
