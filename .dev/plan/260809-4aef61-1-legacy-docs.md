# 기존 30종 문서를 예제 검사기 대상에 편입

## Context

신규 7종(예제 108개)은 CI 가 지키지만 **기존 30종은 여전히 조용히 썩을 수 있다.**
코드블록 307개가 아무도 실행하지 않는 상태다. 이것이 문서 부패를 막는 마지막 구멍이다.

## 실측 (조사 완료)

기존 30종 코드블록 **307개** 중 현재 프리앰블로 통과하는 것은 **53개(17%)**.

**실패 254개의 원인은 대부분 문서 잘못이 아니다.** 프리앰블을 바꿔 재측정했다:

| 프리앰블 | 통과 | 비율 |
| --- | --- | --- |
| `import FunFP` 만 (현재) | 53 | 17% |
| + `Object.assign(globalThis, FunFP)` | **159** | **51%** |

문서를 한 글자도 고치지 않고 106개가 살아난다. 기존 문서가 한 블록에서
`const { Maybe } = FunFP;` 하고 이후 블록에서 맨이름을 쓰기 때문이다.

**`const` 선언이 아니라 `globalThis` 할당이어야 한다** — 블록이 스스로
`const { Maybe } = FunFP;` 를 하는 경우가 많아 `const Maybe` 를 주입하면 충돌한다
(`Identifier 'Maybe' has already been declared`).

남은 실패 **148개**의 분류:

| 원인 | 건수 | 성격 |
| --- | --- | --- |
| `Identifier 'X' has already been declared` | 25 | 블록 안에서 같은 이름을 두 번 선언 — 고칠 수 있다 |
| `SyntaxError: Unexpected/Invalid token` | 29 | 의사코드·출력 예시 — **진짜 실행 불가** |
| `ReferenceError: map/filter/ap/alt/bimap ...` | ~30 | 앞 블록에서 구조분해한 것 — 블록 독립성 위반, 고칠 수 있다 |
| `ReferenceError: fetchUser ...` | 5 | 미정의 헬퍼 — 정의를 넣거나 no-run |
| 라이브러리 런타임 에러 (`unsupported key` 등) | 6 | 개별 판단 |
| 기타 | 나머지 | 개별 판단 |

즉 **진짜 실행 불가는 40개 안팎**이고 나머지 ~108개는 기계적으로 고칠 수 있다.
목표 85%(261개 이상)는 달성 가능하다.

## 변경 사항

### 1. `tests/docs-examples.test.js` — 프리앰블과 대상 변경

```js
// 프리앰블: const 선언이 아니라 전역 할당 (블록의 자체 구조분해와 충돌 방지)
import FunFP from '<index.js>';
Object.assign(globalThis, FunFP);
globalThis.FunFP = FunFP;
```

- **TARGETS 상수를 없애고 `docs/*.md` 전부**를 대상으로 한다. 새 문서가 자동 편입되고
  등록 목록을 잊을 일이 없다.
- **`no-run` 에 이유를 강제한다.** 펜스 정보 문자열이 `no-run` 뿐이고 뒤에 설명이 없으면
  **실패시킨다.** 아무 블록에나 `no-run` 을 붙여 통과시키는 것을 막는 유일한 장치다.
- 문서별 요약과 총계는 그대로. `실행 0개` 가드도 유지한다.

### 2. `docs/*.md` — 블록 수리

회차를 나눈다. 원인별로 처리 방법이 다르다:

- **블록 독립성 위반** (`map is not defined` 등) — 그 블록 첫 줄에 필요한 구조분해를
  추가한다. 예: `const { map } = Functor.of('maybe');`
  독자에게도 낫다 — 페이지 중간부터 읽어도 실행할 수 있다.
- **중복 선언** — 같은 블록이 두 예시를 담고 있으면 변수명을 구분하거나 블록을 나눈다.
- **미정의 헬퍼** — 짧으면 정의를 넣고, 본질이 아니면 `no-run` 으로 이유와 함께 표시.
- **의사코드·출력 예시** — `no-run <이유>`.

### 3. `CLAUDE.md` — (Context 단계에서 완료)

규약을 갱신했다: 대상이 `docs/*.md` 전부, 프리앰블이 모든 export 를 스코프에 올림,
`no-run` 에 이유 필수.

## 회차 분할

| 회차 | 범위 |

| **1 (지금)** | 검사기 개조 + 기존 30종 편입 + 실패 148개 분류 리포트. 이 시점에는 **CI 가 빨간색이 된다** — 의도된 중간 상태다 |
| 2+ | 원인별로 블록 수리. 85% 도달까지 |

**회차 1 끝에 CI 를 빨갛게 두지 않는다.** 편입과 동시에 수리를 시작해, 회차 1 종료 시점에는
`npm test` 가 통과해야 한다. 그러지 못하면 편입을 마지막 회차로 미룬다.

→ **실행 순서**: 검사기를 먼저 고치고(프리앰블), 로컬 스크립트로 남은 실패를 분류한 뒤,
   고칠 수 있는 것부터 고치고, 마지막에 TARGETS 를 열어 `npm test` 가 초록인 상태로 끝낸다.
