# .dev/learning — 판단 규칙 (누적)

`recall` 이 이 파일을 먼저 보여준다. **Context 단계에서 읽어라.**

## 왜 규칙이 여기 있나

`LEARNED.md` 는 하네스가 소유하고 승격 어휘가 `block:`/`tool_fail:` 뿐이다. **판단 실수는
승격 대상이 아니어서** 항상 로드되는 규칙으로 만들 수 없다(하네스 담당자가 별도 회차로 잡음).

그리고 **회차 접두사 파일(`<해시>-<회차>-*.md`)은 설계상 append-only 다** — 다음 회차에서
편집하려 하면 차단된다(2026-08-11 실측). 그래서 **누적되는 규칙의 집은 이 `INDEX.md` 이고,
회차 파일은 그 규칙이 태어난 사건의 기록**이다. 새 규칙은 여기에 추가하고, 근거는 회차
파일로 링크한다.

## 규칙

### 1. 새 것을 만들기 전에 레지스트리를 grep 한다

```
node --input-type=module -e "import fp from './index.js'; console.log(Object.keys(fp.Monoid.types))"
```

**그리고 "없다" 는 사실만 보지 마라 — `git log -S "<이름>" -- <파일>` 로 왜 없는지 봐라.**

### 2. 조회는 "이 **이름**이 있나" 가 아니라 "이 **연산**이 있나" 다 ← 1번의 보강

1번을 지켰는데도 틀렸다. `Monoid.types`/`Semigroup.types` 만 보고 `first` 가 primitive
전용임을 확인한 뒤 새로 만들었는데, **같은 연산이 `Alt`/`Plus` 라는 다른 타입 클래스
이름으로 이미 등록돼 있었다.** 내가 쓴 `(a,b) => a.isJust() ? a : b` 는
`MaybeAlt: (a,b) => a.isNothing() ? b : a` 와 4개 입력 전수에서 객체 동일성까지 같았다.

| 찾는 것 | 볼 곳 |
| --- | --- |
| 결합 연산 (`concat`) | `Semigroup` **+ `Alt`** |
| 항등원 (`empty`) | `Monoid` **+ `Plus`** |
| 사상 (`map`) | `Functor` **+ `Profunctor`(promap)** |

저장소가 이미 그렇게 파생한다 — `MaybePlus` 는 `Alt.types.MaybeAlt` 를 받아 만들어진다.

**회차 2에서 같은 규칙을 다시 어겼다.** 이번엔 레지스트리 것을 골랐는데도 틀렸다 —
`Maybe.Monoid('first')` 는 둘 다 `Just` 일 때 **안쪽 값을 합치고**, `Alt.of('maybe')` 는
**안을 안 본다.** `preview` 가 필요한 것은 후자였고, 전자는 타입이 섞인 대상에서 던졌다
(HEAD 대비 회귀). 전수 대조에서 `Alt` 가 7/7 일치.

**신호**: 같은 결과를 내는 후보가 둘이면 "무엇을 하는가" 가 아니라 **"무엇을 건드리는가"**
로 갈라라. 안을 들여다보는 연산과 안 보는 연산은 실패 조건이 다르다.

**그리고 `fp.fst === undefined` 같은 것은 이름 검색이다.** 회차 5에서 "짝의 왼쪽을 꺼내는
`fst` 는 레지스트리에 없다" 고 주석에 썼는데 **`Comonad.of('array').extract` 가 그 연산이었다.**
이름이 없는 것과 연산이 없는 것은 다르다.

근거: [`260811-15c84c-1-monoid-registration.md`](../review/260811-15c84c-1-monoid-registration.md) §2 ·
[`260811-15c84c-2-first-any.md`](../review/260811-15c84c-2-first-any.md) §1·§2

### 3. YAGNI 로 구조 교정을 기각하지 않는다

`POLICY.md` 6번과 정면 충돌한다. **청구서는 "안 만듦" 이 아니라 "만들어놓고 가둠" 으로
온다** — 사설 Applicative 2개, 사설 Monoid 3개, bare export 11개.

**신호**: "지금은 필요 없다"/"나중에"/"YAGNI" 를 쓰려는 순간, 그것이 **구조를 회피하는
것인지** 자문하라. 회피라면 비용은 0이 아니라 이연될 뿐이다.

근거: [`260811-15c84c-1-judgment-rules.md`](./260811-15c84c-1-judgment-rules.md) §2

### 4. 남의 결정을 가져올 때 그 **전제**가 우리에게 성립하는지 본다

세 번 다 틀렸다 — Haskell 의 `Wander` 난이도(rank-2 타입 강제, JS 엔 없음), `well-typed/optics`
의 내부화 이유(에러 메시지 품질 = 타입 추론 문제), JS optics 선례(`optika`/`monocle-ts` 엔
**레지스트리가 없어서** 감춘 것).

**신호**: 근거로 다른 언어·라이브러리가 인용되면 **그 결정의 이유**를 찾아라. 결론만
가져오면 전제가 따라오지 않는다.

근거: [`260811-15c84c-1-judgment-rules.md`](./260811-15c84c-1-judgment-rules.md) §3

### 5. 구조 변경은 Scaffolding 에서 한다

게이트는 **경로 클래스**만 본다. `.claude/**` 는 `context` 클래스라 Context 단계도 쓸 수
있어 안 걸린다. **"이 종류의 변경이 이 단계에 속하는가" 는 아무도 안 본다 — 스스로 물어라.**

| 단계 | 무엇을 하는 곳인가 |
| --- | --- |
| Scaffolding | **구조** — 폴더링, INDEX, `stages.json`, 정리 |
| Context | **기록** — 계층적 컨텍스트, `CLAUDE.md` 갱신, recall |

근거: [`260811-15c84c-1-judgment-rules.md`](./260811-15c84c-1-judgment-rules.md) §4

### 6. "이제 사용자가 ~할 수 있다" 는 **실행으로 확인한 뒤에만** 쓴다

사설 Monoid 를 레지스트리로 옮기고 주석에 "사설로 만들면 사용자가 바꿔 끼울 수 없다" 고
썼다. 그런데 `const _firstM = Monoid.of('maybe-first')` 는 **로드 시점에 인스턴스를 상수로
캡처**해서, 레지스트리를 갈아끼워도 결과가 안 바뀐다(실측).

**입구 없는 내부 교체는 리팩터링이 아니라 코드 이동이다.** 값은 입구(`foldMap(monoid, …)`
같은)에서 나온다. 입구를 먼저 내면 주장이 코드로 증명된다.

근거: [`260811-15c84c-1-monoid-registration.md`](../review/260811-15c84c-1-monoid-registration.md) §4

### 7. "내부 교체라 동작이 같다" 를 검증 기준으로 쓰려면 **바꾸기 전에** 테스트를 박는다

계획서가 그 문장을 기준으로 삼았고 `npm test` 38 files 가 초록이었는데, `view` 3건이
실제로 달라져 있었다. **바뀐 경로에 테스트가 없으면 초록이 아무것도 증명하지 않는다.**

지금 동작을 먼저 테스트로 박아두면, 바뀌는 순간 빨간불이 켜지고 **"바꿀 것인가" 가
부수 효과가 아니라 결정으로 올라온다.**

근거: [`260811-15c84c-1-verification.md`](../log/260811-15c84c-1-verification.md)

### 8. "있어야 할 것" 을 "있는 것" 으로 쓰지 않는다 ← 두 방향 다

같은 뿌리에서 두 번 나왔다:

| 방향 | 사건 |
| --- | --- |
| 코드에만 있고 문서에 없음 | 사설 딕셔너리 5건 — 만들어놓고 가둠 |
| **문서에만 있고 코드에 없음** | `CLAUDE.md` 에 `Profunctor ──> Strong/Choice/Wander` 계층도. **코드 0건** |

두 번째가 더 나쁘다 — `CLAUDE.md` 는 **항상 로드**되므로 다음 에이전트가 `Strong.of('function')`
을 부르고 `undefined` 를 받는다.

**신호**: 계층도·표·API 목록을 문서에 쓸 때, 그 이름 하나하나를 **실행으로 조회하라.**
`Object.keys(fp.Profunctor.types)` 한 줄이면 된다.

근거: [`260811-15c84c-1-review-gate.md`](../retrospect/260811-15c84c-1-review-gate.md)

### 9. 누적되는 것은 `INDEX.md` 에, 사건은 회차 파일에 ← 마찰 1위

`harness stats` 기준 **`prefix` 미충족이 5개 작업에서 반복** — 전체 1위다. 원인은 대부분
같다: 지난 회차에 만든 파일을 이번 회차에 갱신하려다 막힌다.

**막히는 게 맞다.** `<해시>-<회차>-` 파일은 **그 회차에 무슨 일이 있었는지의 기록**이라
나중에 고치면 거짓이 된다. 갱신하고 싶다는 것은 **그 내용이 회차에 속하지 않는다는 신호**다.

| 성격 | 어디에 |
| --- | --- |
| 누적·갱신되는 것 (규칙, 목록, 색인) | **`INDEX.md`** — 접두사 없이 쓰고 계속 고친다 |
| 그 회차의 사건 (계획, 회고, 검증, 리뷰) | `<해시>-<회차>-*.md` — **한 번 쓰고 안 고친다** |

**신호**: "지난 회차 파일에 한 줄 추가하자" 는 생각이 들면 멈춰라. 그 한 줄의 집은
`INDEX.md` 다. (이 파일 자체가 그렇게 태어났다 — `260811-15c84c-1-judgment-rules.md` 에
규칙을 추가하려다 차단당했다.)

### 10. `cd` 는 다음 Bash 호출까지 남는다 — 절대경로를 쓴다

`harness` 훅 기준 `ls` 실패 3회(작업 2개). 원인은 매번 같았다 — 앞 호출의 `cd` 가 살아
있어 상대경로가 다른 곳을 가리켰다. 체이닝하려면 `cd <절대경로> && ...` 로 매번 고정하라.

### 11. 리뷰 항목을 닫을 때는 "증상이 사라졌나" 가 아니라 "처방을 받아들였나" 로 물어라

회차 1 리뷰 #2 는 중복을 지적하면서 **처방까지 줬다** — "`Plus` → `Monoid` 유도 헬퍼.
`array` 도 같은 중복이 있어 두 건이 함께 해결된다". 회차 2는 중복 클래스를 **지우기만 하고**
그 항목을 해소로 표시했다. 처방을 안 따른 대가로 **같은 지적이 회차 2 리뷰 #2 로 되돌아왔고**,
그 사이에 회귀가 하나 생겼다.

**신호**: 리뷰 항목에 "더 나은 구조는 ~" 이 붙어 있으면, 증상을 지우는 것으로 닫지 마라.
처방을 채택하거나, 채택하지 않는 이유를 적어라.

### 12. 검증 조건은 "무엇이 바뀌었나" 가 아니라 **"바뀐 것이 무엇을 건드리나"** 로 써라

두 회차 연속 같은 방식으로 회귀를 놓쳤다.

| 회차 | 계획서가 쓴 조건 | 놓친 것 |
| --- | --- | --- |
| 1 | "내부 교체이므로 동작이 같아야 한다" | `view` 3건이 달라짐 |
| 2 | "`Maybe.Monoid('first')` 가 원시값·객체 모두 동작하는지" | **둘 다 동종 입력** — 이종에서 던짐 |

회차 2는 "안쪽 값을 합치는 Monoid" 로 갈아끼웠으면 **"inner 가 호출되는 경로가 어디이고
거기 무엇이 흘러들어오나"** 를 물었어야 했다.

**절차가 아니라 도구로 만들어뒀다 — `npm run baseline`.**

```
$ npm run baseline            # HEAD 대비
$ npm run baseline <ref>      # 다른 커밋 대비

=== HEAD 대비 동작 차이 (11/40) ===
  preview 이종            Just(1)
≠ view 다중 [1,2,3]        3  ->  1
≠ Monoid.types 키         [... ] -> [..., "plus(maybe)"]
```

`git show HEAD:index.js` 를 임시 파일로 뽑아 현재 트리와 같은 입력으로 돌리고 **값이든
예외든 같은 모양으로 대조**한다(`tests/baseline.js` 가 엔진, `tests/baseline-report.js` 가
상시 격자 40케이스). 레지스트리 키와 최상위 export 목록도 격자에 들어 있다.

**게이트가 아니라 보고서다** — 차이가 곧 실패는 아니고, 판정은 "이 차이가 계획서에 적혀
있는가" 로 사람이 한다. 그래서 `npm test` 에 넣지 않았다.

**Verification 단계에서 돌리고, 새 표면을 건드렸으면 격자에 줄을 더하라.** 넓히는 비용은
거의 0이고, 좁은 격자가 "차이 3건"(실제 7건) 같은 잘못된 보고를 만든다 — 규칙 17.

`diffCases` 로 임시 격자를 짤 수도 있다:

```javascript
import { diffCases } from './tests/baseline.js';
await diffCases([['라벨', fp => fp.preview(fp.traversed('array'), [1, 'a'])]]);
```

### 13. 테스트는 지적받은 곳이 아니라 **새로 만든 곳**에 써라

회차 2는 리뷰가 지적한 `view` 3건은 **먼저** 썼는데, 그 회차의 본체(`'object'`→`'any'`)에는
0건 썼다. `grep -rn "FirstSemigroup" tests/` → 0건.

**지적받은 것은 기억에 남아 있고, 새로 만든 것은 자기 것이라 의심이 안 든다.**
회차 끝에 물어라 — "이번에 내가 만든 것 중 테스트가 없는 것은?"

**그리고 개수가 기준이 아니다.** 회차 3은 이 규칙대로 본체에 테스트를 10건 썼는데
핵심 하나가 HEAD 에서도 통과하는 어서션이었다. 기준은 **잡는지**다 — 규칙 15를 보라.

### 14. 검증 도구를 만들면 **그 도구가 못 잡는 것을 먼저 나열하라**

회차 3 Scaffolding 에서 회귀 대조 도구(`tests/baseline.js`)를 만들었는데, 그 도구가
**이 라이브러리의 핵심 구분을 숨겼다**:

```
[Just(1), Nothing]         -> [{"value":1,"_typeName":"Maybe"},{"_typeName":"Maybe"}]
[Just(1), Just(undefined)] -> [{"value":1,"_typeName":"Maybe"},{"_typeName":"Maybe"}]   동일
Right(2) / Left(2)         -> 둘 다 {"value":2,"_typeName":"Either"}                     동일
```

`JSON.stringify` 는 `Nothing`/`Just(undefined)`, `Left`/`Right`, `NaN`/`null`/`-0` 을 전부
붕괴시킨다. **차이를 숨기는 대조 도구는 없는 것보다 나쁘다** — 봤다고 착각하게 만든다.

**신호**: 도구를 만든 직후 `Just(undefined)` 같은 경계값 하나를 넣어보라. 5분이다.

### 15. 어서션을 쓰는 순간 **"이게 변경 전에도 통과하나"** 를 물어라

```javascript
assertThrowsWith(() => Semigroup.of('first').concat(1, 'a'), 'must be the same type');
// HEAD 메시지: "...arguments must be the same type and match object"  ← 이것도 포함한다
```

이 테스트는 HEAD 에서도 통과한다 — **아무것도 고정하지 못한다.** 리뷰어가 구현을 되돌리는
뮤테이션으로 적발했다(38 파일 전부 초록).

**부분 문자열 어서션은 대부분 통과한다.** 에러 메시지는 전문으로 대조하고, 반대 분기도
함께 고정하라. 가장 싼 확인은 뮤테이션 — **고친 곳을 되돌리고 테스트가 빨간불이 되는지 보라.**
안 되면 그 테스트는 장식이다.

### 16. "선례가 없다" 는 "못 한다" 가 아니다 ← 규칙 1의 반대편 함정

규칙 1은 "없는 것에는 이유가 있을 수 있다" 였다. 그 반대도 성립한다 — 회차 3에서
"타입 클래스 정적 팩토리는 선례가 없다" 에서 멈추고 손복사 2개로 갔다. 리뷰어가
**실제로 고쳐서 테스트를 돌려** 가능함을 보였다(38 파일 통과, −12줄).

**신호**: "선례가 없어서" 로 구조를 포기하려는 순간, **프로토타입을 만들어 돌려보라.**
`git stash` 가 있으니 비용이 거의 없다. 이유를 찾아보고 없으면 만들면 된다.

### 17. 내가 확인한 표본을 모집단으로 착각하지 마라

회차 3 검증에서 "남는 차이는 `view` 3건" 이라 보고했다. **"3" 은 내가 지운 테스트의 개수**
였다. 격자를 넓히니 7건이었다 (`3→1`, `"a"→1`, `"b"→"a"`, `1→null`, `1→undefined`,
`[2]→[1]`, `{z:2}→{z:1}`).

**신호**: "차이 N건" 이라 쓰려는 순간, 그 N이 **어디서 나온 숫자인지** 물어라. 내가 넣어본
케이스 수인가, 실제 표면인가. 격자 확장 비용은 거의 0이다 — `npm run baseline` 에 줄을 더해라.

### 18. 손으로 쓰기 전에 **"조합으로 되나"** 를 물어라 ← 규칙 1·2 의 한 단계 위

규칙 1·2 는 "이 **인스턴스**가 레지스트리에 있나" 였다. 부족했다. 물어야 할 것이 하나 더 있다 —
**"이 동작을 기존 것의 조합으로 얻을 수 있나."** optics 에서 3회차 동안 아무도 안 봤다:

| 손으로 쓴 것 | 조합 |
| --- | --- |
| `p => ([a,c]) => [p(a), c]` | `Bifunctor.of('tuple').bimap(p, identity, t)` — **완전 일치** |
| `p => e => e.isLeft() ? Left(p(e.value)) : e` | `Bifunctor.of('either').bimap(p, identity, e)` |
| `p => e => e.isLeft() ? p(e.value) : m.empty()` | `Either.fold(p, () => m.empty(), e)` |

그리고 **등록하지 않고 인스턴스를 만드는 정식 경로가 있다** — 생성자의 `registry` 인자를
생략하면 된다:

```javascript
new Applicative(new Apply(new Functor(map, 'Object'), ap, 'Object'), of, 'Object')
```

`_asApplicative` 는 이걸 몰라서 `dict[Symbols.Functor] = true` 로 **심볼을 위조해
`checkAndSet` 검증을 통째로 건너뛰었다.** 등록 여부와 무관하게 클래스를 우회할 이유가 없다.

**조합 후보를 타입 클래스로 좁히지 마라.** 회차 5에서 리뷰어가 찾은 5건 중 3건이 **핵심
유틸리티**였다 — `composeOptic` 이 `compose` 를(같은 파일 127줄, export 됨), `set` 이
`constant` 를, `a => Either.Left(a)` 가 `Either.Left` 를 손으로 다시 썼다. `index.js` 3~370줄이
통째로 그런 것들인데 레지스트리만 뒤졌다.

**그리고 구조 변경의 대가는 숫자로 남겨라.** 검증 우회를 없앤 대가가 `preview` 20배였는데
계획서에 성능 측정 항목이 없었다. `npm run baseline` 은 **값**만 보므로 래퍼가 늘어나는
변경은 격자로 영원히 안 잡힌다.

### 19. 다른 규칙(네이밍·구조)을 들여놓는 것은 **결정이다. 알려라**

optics 섹션에만 언더스코어 접두사 + 약자 10개를 3회차 동안 아무 말 없이 유지했고,
`wander` 같은 Haskell 이름을 설명 없이 썼다. 소유자가 발견하고 말했다 —
**"제가 이해하지 못하면 지워지는 거에요."**

**읽지 못하는 코드는 옳아도 지워진다.** 그리고 이름이 못 지는 짐은 주석이 진다 —
`plus(maybe)` 하나를 설명하는 데 주석 30줄이 들었다.

**신호**: 파일의 다른 곳과 다른 모양을 쓰려는 순간 멈춰라. 왜 다른지 말할 수 없으면
같게 써라. 말할 수 있으면 **말하라** — 커밋 메시지든 주석이든 사람에게든.

### 20. 관측 동등한 변경은 **게이트가 없다**

회차 5의 두 핵심 변경을 뮤테이션으로 되돌려봤다:

| 되돌린 것 | 결과 |
| --- | --- |
| `Bifunctor` 조합 → 손코드 | 38/38 통과 |
| 클래스 Applicative → **심볼 위조** | **38/38 통과** |

둘 다 관측 동등이라 테스트로도 `npm run baseline` 격자로도 **원리적으로 못 잡는다.**

**"합성으로 썼는가" 를 지키는 것은 `staticland-reviewer` 뿐이다.** 초록불을 "규칙을 지켰다"
로 읽지 마라 — 리팩터·검증 복원·조합 치환은 전부 이 범주다.

**게이트를 만들 수 있는 유일한 길은 등록이다.** `Applicative.of('identity')` 로 꺼낼 수
있으면 `instanceof`·검사 동작을 테스트로 고정할 수 있다. 그래서 등록은 구조 교정이면서
동시에 **검증 수단**이다 — 미루면 검증 수단을 그만큼 없이 둔다.

### 21. 오래 걸리는 도구는 **먼저 말하고 부르거나 백그라운드로 돌려라**

`staticland-reviewer` 는 회차당 **30~48분**이 걸리고 `run_in_background: false` 면 그동안
**턴이 통째로 막힌다** — 사용자가 말을 걸어도 답이 안 나간다.

회차 3·4·5에서 각각 40분·33분·48분을 그렇게 썼고, 사용자가 48분째에 "48분 동안 돌고 있는
스크립트 뭐죠? 답변하지 않으니 강제 종료합니다" 라고 물었다. **백그라운드 잡이 아니라
내가 자초한 블로킹이었다.**

**신호**: 이전에 10분 넘게 걸린 도구를 다시 부르려는 순간 — ① 예상 소요를 먼저 말하거나
② `run_in_background: true` 로 돌리고 그 사이 다른 일을 하라. **검증의 질만 보고 대화가
멈추는 비용을 빼먹지 마라.**

### 22. 새 이름을 만들 때는 **관례를 실행으로 조회하고 대조**하라 ← 세 번 걸렸다

| 사건 | 무엇이 어긋났나 |
| --- | --- |
| `_PFn`/`_PForget`/`_runOptic` … 10개 | optics 에만 언더스코어 접두사 + 약자. 나머지는 `emptyFunc`/`identity`/`raise` |
| `maybe-first` | 기존 매개변수화 키는 `maybe(first)`·`statet(maybe)` 로 **괄호 형식** — 하이픈은 조립이 안 된다 |
| `optics` (소문자) | 안에 `Lens`/`Prism`/`Iso` 생성자가 주인공이라 `Optics` 가 맞았다 |

**셋 다 소유자가 잡았다. 내가 잡은 것은 하나도 없다.**

```
Object.keys(fp).filter(k => k[0] === k[0].toUpperCase())   // 대문자 = 타입/타입클래스 38개
Object.keys(fp).filter(k => typeof fp[k] === 'object')     // 모듈 객체 (transducer, extra, Optics)
Object.keys(Monoid.types)                                   // 레지스트리 키 형식
grep -n "^const _" index.js                                 // 언더스코어 관례
```

**판정**: 새 이름이 같은 범주의 기존 이름들과 **형태가 같은가.** 다르면 그 이유를 적어라.
적을 수 없으면 관례를 따르라.

**기계로 막았다** — `staticland-reviewer` 의 판정 기준에 **유형 6·7 로 넣었다**
(`.claude/agents/staticland-reviewer.md`). 이제 새 이름이 하나라도 있으면 리뷰어가
관례를 조회해 대조한다. 산문으로만 남기면 또 놓친다.

**부수 신호 (유형 7)**: 새 이름 하나에 주석이 5줄 이상 붙으면 **이름이 틀린 것**이다.
`plus(maybe)` 하나에 `CLAUDE.md` 12줄 + `index.js` 17줄이 들었다.

### 23. 검증 도구는 **없는 차이를 만들 수도 있다**

규칙 14는 "도구가 차이를 **숨긴다**" 였다. 반대 방향도 있다.

optics 이름 이동에 맞춰 `baseline` 격자에 정규화 shim 을 넣었는데:

```javascript
const compose = o.compose ?? o.composeOptic;   // HEAD 에는 f.compose(범용 합성)가 있다
```

`??` 가 optic 합성 대신 **범용 함수 합성**을 골라 **거짓 회귀 3건**이 떴다
(`P.first is not a function` 등). `f.Optics` 유무로 갈라 고쳤다.

**신호**: 도구가 회귀를 보고하면 **도구를 먼저 의심하라.** 특히 이름·경로를 정규화하는
코드가 들어간 직후라면. 규칙 20이 말하듯 관측 동등한 변경에는 게이트가 없으므로,
격자가 갑자기 빨개지면 코드가 아니라 격자가 바뀐 것일 확률이 높다.

### 24. **사용자가 결정하는 자리에 놓는 근거**는 코드 주장보다 엄격하게 확인하라

`optics` vs `Optics` 를 물으면서 근거 표를 붙였다:

> "대문자 38개는 전부 `.of()` 를 가진 타입이고 소문자 3개는 함수 묶음입니다"

**거짓이었다.** 대문자 39개 중 7개는 `.of` 가 없고(`Algebra`/`StateT`/`EitherT`/`ReaderT`/
`WriterT`/`Actor`/`Optics`), 실재하는 관례는 "IIFE 함수 묶음은 소문자"(2/2)였다.
**사용자는 그 표를 보고 결정했다.**

규칙 6("이제 사용자가 ~할 수 있다 는 실행으로 확인한 뒤에만 써라")이 이미 있었는데
**"코드의 주장" 에만 적용하고 "사람에게 주는 근거" 에는 적용하지 않았다.**

**신호**: 선택지에 숫자·표·분포를 붙이려는 순간 — 그것을 **먼저 실행하라.** 코드가 틀리면
테스트가 잡지만, 사람에게 준 근거가 틀리면 **결정이 오염되고 아무도 안 잡는다.**

이 사건 뒤 `CLAUDE.md` 에 「이름 규칙」 절을 만들어 실측 분포와 조회 명령을 박았다 —
**조회할 곳이 없으면 또 지어낸다.**

### 25. 선례를 따를 때는 **그 이름으로 파일 전체를 grep** 해 구성 요소를 대조하라

`Maybe.Monoid(innerSG)` 를 선례로 `Applicative.Const(monoid)` 를 만들었다. 대조표:

| 선례의 구성 | 따라했나 |
| --- | --- |
| `_keyCache` / `_instanceCache` 쌍 | ✅ |
| 키 해석기 | ✅ |
| `<바깥>(<키>)` 로 레지스트리 등록 | ✅ |
| **`addResolver` — 지연 해석기** | ❌ **빼먹었다** |

```
Monoid.of('maybe(first)')      — 팩토리 호출 전에도 OK   ← addResolver 덕분
Applicative.of('const(array)') — 팩토리 호출 전  THROW
```

**정의부(1403~1437줄)만 읽고 60줄 아래의 `addResolver`(1498줄)를 안 봤다.**
선례는 한 곳에 모여 있지 않다.

**신호**: "X 선례를 따른다" 고 쓰는 순간 `grep -n "X" index.js` 로 **X 가 등장하는 모든 줄**을
보고 구성 요소를 목록으로 만들어라. 그다음 하나씩 대조하라.

그리고 **완료 조건에 "선례와 동일하게 동작한다" 를 넣어라** — 이번엔 조건이
`Applicative.of('const(array)')` 만 물어서, 선례가 *호출 전에도* 된다는 것을 안 봤다.

### 26. **주석으로 막았다면 아직 안 막은 것이다**

앞 회차 리뷰가 `type: 'Object'` 대문자를 「위태로운 결합」이라 지적했다
(`types.equals(a,b,'Object')` 는 대소문자 폴백이 없고, 같은 파일의 `ObjectFilterable` 은
소문자를 쓴다 — "일관성" 으로 정리하면 optics 가 통째로 죽는다).

**나는 주석을 달고 처리했다고 표시했다.** 주석은 읽는 사람에게만 작동한다.

그리고 **뮤테이션은 "몇 개가 깨지나" 가 아니라 "깨진 메시지가 원인을 가리키나" 까지 봐야
한다.** 이 자리는 전부터 2개가 깨지고 있었다 — 그런데 둘 다 증상(`Apply.ap: both arguments
must be object`)만 보여주고 **왜 그렇게 됐는지는 안 알려줬다.** 세 번째 테스트를 넣으니
이름이 답을 준다.

**신호**: 「위태롭다」·「주의하라」·「누가 바꾸면」 같은 지적을 받으면 — **주석이 아니라
테스트로 답하라.** 규칙 11(처방을 받아들였나)의 특수 경우다.

### 27. 자체 감사는 **"고친 자리" 가 아니라 "유형"** 으로 하라

리뷰어 결과와 자체 감사를 대조했더니 **5건 중 4건이 "같은 것이 다른 곳에도 있다"** 였다:

| 내가 고친 것 | 못 본 것 |
| --- | --- |
| `identity` 를 3단 등록 | **30줄 아래** `Applicative.Const` 는 옛 모양 그대로 |
| `preview`/`toList` 에 자기 검사 | `runOptic` 의 남은 도달 경로(`over`/`foldMapOf`) |
| `docs/` 의 옛 이름 제거 | `index.js` 주석 3곳 |
| `Applicative.Const` 에 키 수용 | 그것을 부르는 `foldMapOf` |

**내 감사 범위가 좁은 게 아니라 방향이 다르다.** 나는 지적받은 좌표를 고치고 그 좌표를
다시 본다. 리뷰어는 그 **유형**으로 파일 전체를 훑는다.

**신호**: 지적을 고쳤으면 **그 유형으로 grep 하라.** "익명 Functor/Apply", "자기 검사 없는
연산", "옛 이름" — 좌표가 아니라 패턴으로.

### 28. 백그라운드 작업을 띄웠으면 **그 대상 파일을 건드리지 마라**

리뷰어 28분 동안 `index.js` 가 **네 번 바뀌었고** 리뷰어가 "이 리뷰의 전제가 깨졌다" 로
리포트를 시작했다. 브리핑의 절반이 이미 사실이 아니었다.

**규칙 21(백그라운드로 돌려라)의 짝이다.** 도구 설명에도 *"avoid working with the same
files"* 라고 있다 — 읽고도 같은 파일에 회차 두 개를 더 진행했다.

**신호**: 백그라운드 리뷰를 띄우면 그동안 **문서·테스트·다른 모듈**을 하거나, 아예 다음
회차를 열지 마라.

### 29. 주석이 길어지면 **문서 예제로 옮겨라**

`plus(maybe)` 와 `maybe(first)` 의 차이를 설명하는 데 `CLAUDE.md` 12줄 + `index.js` 17줄 =
**주석 29줄**이 들었다. 앞 리뷰가 "이름이 못 지는 짐을 주석이 진다" 고 지적한 그것이다.

`docs/*.md` 는 **예제가 전부 실행 검사**를 받는다. 옮기면 **예제가 곧 회귀 테스트**가 된다 —
둘의 관계가 바뀌면 빌드가 빨개진다. 주석은 그렇게 안 된다(규칙 26의 짝).

**단 검사기는 "예외 없이 끝나는지" 만 본다** — 주석의 `// 1` 같은 기대값은 대조하지 않는다.
**기대값은 사람이 따로 실행해 확인해야 한다.** 이번엔 15개를 대조했다.

## 이것들을 기계로 막는 방법

| | 상태 |
| --- | --- |
| `staticland-reviewer` 에이전트 | ✅ 규칙 1·3·4·8 을 사냥하도록 프롬프트에 박힘 |
| `review` 노드 (`.dev/review/` 기록 강제) | ✅ `path add review` 로 회차에 넣는다. 2026-08-11 첫 가동에서 6건 검출 |
| `LEARNED.md` 승격 | ❌ 판단 실수는 승격 어휘에 없다 — 하네스 담당자가 별도 회차로 |
| 이 파일 | ⚠ `recall` 이 Context 에서 끌어와야 작동한다 |

**규칙 2·6·7 은 아직 사람이나 리뷰어가 잡아야 한다** — 리뷰어 프롬프트에 넣을 후보다.
