# `.dev/` — 작업의 흔적

에이전트가 쓰는 폴더입니다. 소스도 문서도 아니고, **어떻게 여기까지 왔는지의 기록**입니다.

**예외가 하나 있습니다 — [`TODO.md`](./TODO.md) 는 「지금 어디인가」입니다.**
나머지 전부가 과거형이고 그것만 현재형입니다. 작업을 시작할 때 먼저 읽고, 상태가 바뀔 때마다
고치십시오. 세션 기억은 세션과 함께 사라지지만 이 파일은 남습니다.

## 파일 이름

```
YYMMDD-<slug>.md              260812-optics-module.md
YYMMDD-<slug>-<구분>.md        260812-optics-module-perf.md   같은 날 같은 작업의 두 번째
```

- **날짜가 앞** — `ls` 가 곧 시간순입니다.
- **슬러그는 작업을 가리킵니다.** 여러 날에 걸치면 날짜만 바뀌고 슬러그는 유지합니다.
  `grep -r optics-module .dev/` 로 한 작업의 산출물이 폴더와 무관하게 모입니다.
- **증가 번호(`001`, `002`)를 쓰지 마십시오** — 워크트리로 병행하면 충돌합니다.
  슬러그는 내용에서 나오므로 자연히 갈립니다.

### 예외: `INDEX.md`

접두사 없이 쓰고 **계속 고칩니다.** 폴더마다 하나씩 둡니다.

| | 성격 |
| --- | --- |
| `YYMMDD-<slug>.md` | 그날의 사건 — **한 번 쓰고 안 고친다.** 나중에 고치면 거짓이 된다 |
| `INDEX.md` | 누적되는 것(규칙·목록·색인) — **계속 고친다** |

"지난 파일에 한 줄 추가하자" 는 생각이 들면 멈추십시오. **그 한 줄의 집은 `INDEX.md` 입니다.**

### 옛 접두사

`260812-a866ff-1-docs.md` 처럼 `<날짜>-<해시>-<회차>-` 인 파일이 95개 있습니다.
**하네스(step-seven-harness)를 쓰던 시기의 것**이고, 서로를 파일명으로 88번 참조하므로
**이름을 바꾸지 않습니다.** 새 파일만 위 규칙을 따릅니다.

## 폴더

| | 무엇을 넣나 |
| --- | --- |
| `plan/` | 무엇을 왜 어떻게 할지. **실행 전에** 쓰고, 끝난 뒤 대조한다 |
| `log/` | 조사·검증 기록. 실행 결과와 그 해석 |
| `review/` | 적대적 검토 결과와 각 지적의 처리 |
| `retrospect/` | 무엇이 통했나 / 무엇을 잘못 가정했나 / 이 회차를 싸게 만들었을 것 |
| `learning/` | 회고에서 뽑은 **판단 규칙**. `INDEX.md` 가 본체다 |
| `experiment/` | 버려도 되는 탐색. 결론만 다른 폴더로 옮긴다 |

## 왜 남기나

**같은 실수를 두 번 하지 않기 위해서입니다.** 그것이 안 되면 이 폴더는 일기일 뿐입니다.

작업을 시작할 때 `.dev/*/INDEX.md` 를 먼저 읽으십시오 — 특히
[`learning/INDEX.md`](./learning/INDEX.md)(판단 규칙)와
[`retrospect/INDEX.md`](./retrospect/INDEX.md)(무엇이 실제로 반복됐나).
