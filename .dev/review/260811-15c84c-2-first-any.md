### 1. `preview`/`view` 가 **타입이 섞인 대상에서 던진다** — HEAD 는 첫 대상을 돌려줬다 ← **회귀**

`_firstM = Maybe.Monoid('first')` (`index.js:2307`) 가 원인이다. `Maybe.Monoid(innerSG)` 는
둘 다 `Just` 일 때 **안쪽 값을 `innerSG.concat` 으로 합친다.** 그 순간 strict 검사가
"두 인자가 같은 타입" 을 요구한다.

| 입력 | HEAD | 현재 |
| --- | --- | --- |
| `preview(traversed('array'), [1,'a'])` | `Just(1)` | **TypeError** |
| `preview(traversed('array'), [null,1])` | `Just(null)` | **TypeError** |
| `view(traversed('array'), [1,'a'])` | `'a'` | **TypeError** |
| `toListOf(traversed('array'), [1,'a'])` | `[1,'a']` | `[1,'a']` (영향 없음) |

직접 재현했다. 합성 optic 의 현실적 케이스도 같다 —
`preview(composeOptic(traversed('array'), Lens(o=>o.nick, …)), [{nick:null},{nick:'ann'}])`
가 `Just(null)` → TypeError.

에러 메시지가 `Semigroup.concat:` 이라 호출자는 `preview` 에서 왔다는 단서를 못 받는다.

**계획서 Verification 1번이 동종 입력만 확인하도록 쓰여 있어 이 회귀를 구조적으로 못 보게
돼 있었다.** 회차 1 리뷰 #6("동작이 같아야 한다는 기준이 깨졌다")이 **함수만 바꿔 재발했다.**

### 2. 레지스트리에 이미 답이 있었다 — `Alt.of('maybe')` + `Plus.of('maybe')` 가 HEAD 와 7/7 일치

직접 전수 대조했다:

| 케이스 | `Alt.of('maybe').alt` | `Maybe.Monoid('first')` |
| --- | --- | --- |
| `J1,J2` / `J1,N` / `N,J2` / `N,N` | 일치 | 일치 |
| `Just(1), Just('a')` | `Just(1)` | **THROW** |
| `Just(null), Just(1)` | `Just(null)` | **THROW** |
| `Just({}), Just([])` | `Just({})` | **THROW** |
| `zero()` | `Nothing` | `Nothing` |

**`preview` 가 하는 일은 "첫 `Just` 를 통째로 고르기" 지 "안쪽 값 합치기" 가 아니다.**
`Alt` 는 안을 안 들여다보고, `Maybe.Monoid(innerSG)` 는 들여다본다. 의미가 다르다.

이것은 **내가 이번 세션에 직접 승격한 규칙 #56** 이다 —
"`concat` 을 찾을 땐 `Semigroup` 뿐 아니라 `Alt` 를, `empty` 는 `Monoid` 뿐 아니라 `Plus` 를 봐라."
그리고 **회차 1 리뷰 #2 가 이미 같은 처방을 냈다** — "`Plus` → `Monoid` 유도 헬퍼".
나는 그 처방을 채택하지 않고 4개 클래스를 지우는 것만으로 #2 를 해소 처리했다.

**처방**: `Plus`→`Monoid` 유도를 레지스트리 관례로 낸다. `Monoid.types['maybe']`/`['array']`
가 등록되면 `const _firstM = Monoid.of('maybe')` 가 되어 `_arrayM = Monoid.of('array')` 와
대칭이 되고, `Alt`/`Plus` 를 가진 임의 타입으로 확장된다.

### 3. 주석이 없는 `foldMap` 경로를 있다고 말한다 ← **리뷰 #4 의 재발**

`index.js:2305` 에 내가 쓴 것: `// 사용자가 다른 Monoid 로 모으는 길은 foldMap 으로 낸다`

`foldMap` 은 `index.js:1892` 에 **존재하고 export 되지만 Foldable 전용이라 optic 을 안 받는다.**
`foldMap(traversed('array'), Monoid.of('number'))(x=>x)([1,2,3])` → `TypeError: foldMap: first
argument must be a Foldable`.

시제 없이 "낸다" 로 확정 서술했다. 회차 1 리뷰 #4("주석이 코드에 없는 이득을 주장")가
형태만 바꿔 재발했다. **한 단어로 고쳐진다** — "낼 예정이다 (아직 없다 — 회차 4)".

부수: 계획서 자체가 `foldMap` 을 C 절에서는 "회차 3", 하단 표에서는 "회차 4" 로 적어 불일치.

### 4. `'any'` 를 `checkAndSet` 이 아니라 범용 `types.check` 에 넣었고 문서가 없다

`CLAUDE.md` 「검증 로직 분리 (checkAndSet)」 — "검증 로직은 한 곳에서 일관되게 관리".

`types.check` 소비자 **13곳**: Setoid·Ord·Semigroup·Group·Filterable·Functor·Bifunctor·
Chain·Foldable·Extend·Comonad·Traversable·`sequence`. 즉 `'any'` 는 그 전부에서 값 타입
검사를 무력화하는 예약어가 됐다.

- `grep -rn "'any'" docs/ CLAUDE.md types/` → 실질 1건 (d.ts 주석뿐)
- `types.check(null, 'any')` → `true`. `first`/`last` 엔 무해하나 다음 사람이 `Functor` 나
  `Traversable` 을 `'any'` 로 등록하면 **컨테이너 검사가 통째로 사라진다.** 막는 장치도
  경고 문장도 없다
- 계획서 스스로 "A 는 타입 시스템 전역에 닿는다" 고 인정해놓고 문서화는 d.ts 주석 한 쌍으로 끝냈다

**레지스트리 오염은 없음이 확인됐다** — `register()` 는 `instance.type` 을 안 쓴다.
`Semigroup.of('any')` → `TypeError: unsupported key any`.

**처방**: `CLAUDE.md` 「검증 로직 분리」 절에 명시 — 무엇을 끄고(값 타입) 무엇을 안 끄는지
(`types.equals`), 그리고 **"이항 연산(Setoid/Ord/Semigroup)에만 쓴다 — 단항 검사에 쓰면
검사가 완전히 사라진다"**.

## 이 회차가 증명한 것

**진단이 옳아도 처방은 틀릴 수 있다.** 근거 3개가 전부 실측으로 확인됐는데도 처방이
회귀를 냈다. 근거 검증과 처방 검증은 다른 일이다.

그리고 **내가 이번 세션에 승격한 규칙(#56)을 같은 세션에서 다시 어겼다.** 회차 1은
"거울상"이었고 회차 2는 "그대로 재발" 이다. 규칙을 쓰는 것과 적용하는 것 사이의 간격이
회고로는 안 좁혀진다는 증거다 — 리뷰어가 없었으면 세 번째도 갔다.
