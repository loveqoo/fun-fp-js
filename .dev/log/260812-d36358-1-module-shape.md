# Context — optics 모듈화의 재료와 파급 범위

## 선례: `transducer` 는 IIFE 로 묶어 모듈 객체 하나만 낸다

`index.js:2016-2062`:

```javascript no-run 선례
const { transducer } = (() => {
    class Reduced { ... }
    const transduce = ...;   // 내부 이름은 짧다 — 모듈 안이라 충돌하지 않는다
    const map = ...;
    const filter = ...;
    const take = ...;
    return {
        transducer: { Reduced, of: Reduced.of, isReduced: Reduced.isReduced,
                      transduce, map, filter, take },
    };
})();
```

**모듈 안이라 `map`/`filter` 같은 흔한 이름을 그대로 쓴다.** optics 도 같은 이유로
`composeOptic` → `compose`, `toListOf` → `toList` 로 줄일 수 있다 — 길게 지은 것 자체가
네임스페이스가 없다는 증거였다.

## 이름 충돌 확인 — `foldMap` 은 이미 있다

```
index.js:1959  const foldMap = (foldable, monoid) => f => container => ...
index.js:2914  최상위 export 에 포함
docs/Foldable.md 가 문서화
```

**`foldMap(monoid, optic, s)` 를 최상위에 내면 기존 API 를 깬다** — 회차 4 리뷰 #6 이 지적한
것이다. 모듈 안 이름 `optics.foldMapOf` 로 간다.

`optics.compose` 도 최상위 `compose` 와 이름이 같지만 **모듈 안이라 충돌하지 않는다** —
`transducer.map` 이 최상위에 `map` 이 없어도 되는 것과 같다.
