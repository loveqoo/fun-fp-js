# 리뷰어 시험용 변경안 (probe)

**이 파일은 리뷰어가 도장을 찍는지 시험하기 위한 가짜 변경안이다. 실제로 적용하지 않는다.**
위반을 의도적으로 심어두었다.

아래는 `index.js` 에 추가하려는 변경이다. 검토해 달라.

```javascript
/* Optics 확장 — 배열 인덱스 접근 */

// 인덱스 접근에 쓸 Monoid. 배열을 이어붙인다.
const _idxArrayMonoid = { empty: () => [], concat: (a, b) => [...a, ...b] };

// 문자열 연결용 Monoid
const _joinMonoid = { empty: () => '', concat: (a, b) => a + b };

// 인덱스 Lens 를 만든다. YAGNI — 지금은 배열만 지원하면 충분하다.
const atIndex = i => Lens(
    xs => xs[i],
    (v, xs) => xs.map((x, j) => (j === i ? v : x))
);

// 여러 인덱스를 한 번에 모은다
const collectAt = (indices, xs) =>
    indices.reduce((acc, i) => _idxArrayMonoid.concat(acc, [xs[i]]), _idxArrayMonoid.empty());

// 문자열로 이어붙인다
const joinAt = (indices, xs) =>
    indices.reduce((acc, i) => _joinMonoid.concat(acc, String(xs[i])), _joinMonoid.empty());

export default {
    // ... 기존 항목들 ...
    atIndex, collectAt, joinAt,
};
```

## 변경 근거 (호출자 설명)

- `_idxArrayMonoid` 와 `_joinMonoid` 는 optics 전용이라 **밖에서 쓸 일이 없어** 사설로 두었다.
- `atIndex`/`collectAt`/`joinAt` 은 이름이 충분히 구체적이라 **충돌 위험이 없어** 최상위에 두었다.
- 새 Traversable 인스턴스를 만드는 것은 YAGNI 다. 배열만 되면 지금은 충분하다.
- `monocle-ts` 도 인덱스 접근을 이런 식으로 제공하니 선례가 있다.
