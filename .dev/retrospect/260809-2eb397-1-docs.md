## 1. 무엇이 통했나

**문서보다 검사기를 먼저 만든 것.** 순서가 결과를 바꿨다. 검사기가 있으니 문서를 쓰는 동안
서술이 **세 번 교정**됐다 — 전부 내가 맞다고 믿고 쓴 뒤 실행에서 틀린 것들이다:

| 교정된 서술 | 실제 |
| --- | --- |
| `composeLens` 인자 순서 | 바깥→안쪽 (`tests/optics.test.js:69` 로 확인) |
| transducer `compose(a, b)` 데이터 흐름 | **함수 합성과 반대** — 데이터는 `a` 를 먼저 통과 |
| `transducer.take` 재사용 가능 여부 | 미적용은 재사용 가능, **미리 적용한 것은 소진됨** |

검사기를 나중에 붙였다면 이 셋은 문서에 그대로 실렸을 것이다. 세 번째는 실행해보기 전까지
나도 몰랐던 함정이라 오히려 문서의 가치 있는 항목이 됐다.

**"0개 실행하고 초록불" 을 가드로 막은 것.** 검사기에서 가장 위험한 실패는 예제가 틀리는
게 아니라 **아무것도 실행하지 않고 통과하는 것**이다. allowlist 오타 하나면 그렇게 된다.
`totalRun === 0` 이면 실패시키는 가드를 넣고, 파일명을 `Lenz.md`/`Aktor.md` 로 망가뜨려
실제로 잡히는지 확인했다. 검증 도구를 만들 때 **"도구가 놀고 있어도 초록불인 경로"** 를
먼저 찾아 막는 것이 일반 규칙이다 (회차 전 작업에서 actionlint 로 같은 걸 했다).

**파일명을 `tests/docs-examples.test.js` 로 지은 것.** `*.test.js` 패턴에 걸려
`tests/run.js` 가 자동으로 집어가고, 프로세스 격리와 exit code 처리를 공짜로 상속했다.
러너도 CI 도 한 줄도 고치지 않았다. **기존 구조에 이름으로 편입되는 쪽이 배선을 추가하는
쪽보다 낫다.**

**비동기 예제를 헛되이 통과시키지 않은 것.** Actor 예제는 `fork` 콜백이 돌기 전에 블록이
끝나면 통과해버린다. 쓰기 전에 `await new Promise((res, rej) => task.fork(rej, res))` 형태로
실패가 exit 1 이 되는지 먼저 확인했다. 덕분에 "100건 동시 전송 → 정확히 100", "순서 보장",
"에러 격리" 같은 주장이 **글이 아니라 실행으로** 뒷받침된다.

## 2. 무엇을 잘못 가정했나

**기존 30종 문서의 예제가 실행 가능할 것이라 막연히 생각했다.** 조사해보니 코드블록 324개
중 108개가 `FunFP` 전역을 쓰는데 그 전역을 만드는 import 가 없고, `fetchUser` 같은 미정의
헬퍼를 쓰는 블록도 많다. **문서 예제는 "보여주기용" 으로 쓰이면 실행 가능성이 없다.**
→ 신규 7종만 allowlist 로 검사하기로 범위를 좁혔다. 기존 30종 편입은 별도 작업이다.

**transducer 합성 방향을 함수 합성과 같다고 가정했다.** `compose(a, b)` 는 `a(b(x))` 이므로
데이터가 `b` 를 먼저 통과할 것이라 생각했는데, transducer 는 **리듀서를 감싸는 순서와
데이터가 흐르는 순서가 반대**다. 실행해서 `[4,8]` 과 `[2,4,6,8,10]` 이 갈리는 것을 보고서야
알았다. 이런 건 소스를 읽어도 헷갈리고 **돌려봐야 확실해진다.**

## 3. 이 회차를 싸게 만들었을 것은

**`tests/` 를 문서 재료로 쓸 생각을 더 일찍 했다면.** Context 후반에야 "테스트가 이미 검증된
예제" 라는 걸 활용하기 시작했다. `tests/optics.test.js` 의 fixture 를 그대로 가져오니
Lens 문서가 빨리 정확해졌다. **문서를 쓸 때 1차 재료는 소스가 아니라 테스트다** — 소스는
무엇이 가능한지 알려주고, 테스트는 무엇이 실제로 동작하는지 알려준다.

**회차 분할을 Selection 에서 명시했으면.** Planning 에 가서야 "한 회차에 안 끝난다" 를
인정하고 표로 적었다. 완료 조건 8개 중 4개가 회차 2 몫이라는 걸 처음부터 알고 있었으므로,
Selection 에서 분할을 적어뒀다면 Planning 이 짧아졌다.

**이 회차는 차단이 0건이었다.** 직전 두 회고의 규칙(쓰기 클래스 선확인, 화이트리스트 사본)을
적용한 결과다 — `CLAUDE.md` 를 Context 단계에서 미리 썼고, 컨테이너 사본도 필요한 파일만
열거했다. 회차 1: 차단 1건 → 회차 2: 차단 3건 → 이번: **0건**.
