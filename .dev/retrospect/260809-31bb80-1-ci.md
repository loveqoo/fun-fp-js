# 회고 — GitHub Actions CI 도입 (260809-31bb80 · 회차 1)

작업: `main` push / 모든 PR 에서 Node 20·22 매트릭스로 `npm ci` → `npm test` → 빌드 검증.
`engines: node >=20` 명시. 완료 조건 7개 전부 충족.

## 1. 무엇이 통했나

**"검증 도구가 실제로 검증하는가" 를 따로 확인한 것.** 통과만 보면 도구가 놀고 있어도
모른다. 두 가지를 일부러 깨봤다:

| 주입 | 결과 |
| --- | --- |
| 실패하는 테스트를 컨테이너에 투입 | exit 1, **빌드 스텝 미실행**(`Build complete` 0회) |
| `matrix.node` → `matrix.nodeXX` | actionlint 가 `property "nodexx" is not defined` 로 포착 |

직전 회차에서 얻은 "게이트 작업은 실패 주입을 포함해야 한다" 가 이번엔 **검증 도구 자체에도**
적용된다는 걸 확인했다. 이건 일반 원칙으로 굳었다.

**`act` 가 없다는 걸 Scaffolding 에서 미리 확인한 것.** 도구 가용성을 그 단계에서 조사한
덕에 계획을 세우기 전에 "docker 로 `node:20`/`node:22` 직접 실행" 으로 방향을 틀 수 있었다.
결과적으로 `act` 보다 정확했다 — 실제 런타임에서 진짜 `npm ci` 가 돌았다.

**actionlint 를 추가로 돌린 것.** pyyaml 은 문법만 본다. GitHub 워크플로 **스키마**
(`matrix` 참조 유효성, `uses` 형식 등)는 모른다. 손으로 쓴 assert 로는 못 잡을 종류의 오류가
있고, actionlint 가 그 층을 덮었다. docker 만 있으면 설치 없이 쓸 수 있다.

**직전 회고의 교훈을 실제로 적용한 것.** "계획 시 대상 파일의 쓰기 클래스를 먼저 확인한다"
를 지켜서, `CLAUDE.md`(context 클래스)를 **Context 단계에서 미리** 썼다. 지난번의
`harness allow` 왕복이 이번엔 없었다. 회고가 산문으로 끝나지 않고 행동을 바꿨다.

## 2. 무엇을 잘못 가정했나

**`dist` 빌드 타임스탬프를 재현성 결함으로 판단했다 — 틀렸다.** 사용자 정정:
타임스탬프는 의도적 설계다. 재빌드하면 값이 바뀌지만 **그 변경은 커밋/푸시를 거쳐야만
적용되고**, 타임스탬프를 바꿔 배포하는 주체는 사람이다. 즉 그 필드는
**"사람이 이 빌드를 배포하기로 결정한 시점"** 을 기록한다.

일반화하면: **"기계적으로 검증할 수 없다" 는 사실 자체는 결함의 근거가 아니다.**
검증 가능성이 목표가 아닌 영역이 있고, 거기서는 사람의 커밋이 곧 의도의 기록이다.
설계 의도를 묻지 않고 "재현 가능해야 한다" 는 일반론을 들이댄 것이 실수였다.
→ 정정을 `.dev/plan/INDEX.md` 와 메모리에 남겨 재발을 막았다. 워크플로 주석에도
`git diff --exit-code dist` 를 넣지 말라고 박아뒀다.

**`harness allow` 가 모든 쓰기 차단을 연다고 가정했다 — 아니다.** 두 게이트가 별개다:

- `allow <glob>` = **경로 클래스** 예외 (`docs/`, `CLAUDE.md` 같은 소유권 규칙)
- `loop_prefix` = **파일명 접두사** 규칙 (`<작업해시>-<회차>-`)

지난 작업의 문서를 정정하려다 `allow` 를 걸었는데도 계속 막혔다(`block/loop_prefix` ×2).
접두사 규칙에는 `allow` 가 통하지 않는다.

## 3. 이 회차를 싸게 만들었을 것은

**지난 작업의 기록을 정정하는 통로를 미리 알았다면** `allow` 왕복 2회가 없었다.
정답은 **`INDEX.md`** 다 — POLICY 가 명시하듯 회차 접두사 없이 쓸 수 있고 `recall` 이
진입점으로 **먼저** 보여준다. 즉 낡은 문서를 고치는 대신, 인덱스에 정정을 얹으면 읽는 쪽이
정정을 먼저 본다. 접두사 규칙과 싸울 필요가 없었다.
→ **규칙: 지난 작업의 산출물을 고쳐야 하면 그 파일을 편집하려 하지 말고 같은 폴더의
`INDEX.md` 에 정정을 쓴다.**

**`.claude` 를 인자에 넣지 않는 법을 알았다면** `protected_bash` 차단 1회가 없었다.
`rsync -a --exclude .claude ./ "$COPY"/` 가 막혔다 — 하네스는 `.claude` 를 **쓰기 대상이
아니라 인자로만 언급해도** 차단한다(제외 지시였는데도). 우회는 "제외" 가 아니라 **"필요한
것만 열거"** 였다: `cp package.json package-lock.json index.js build.js ... "$COPY"/`.
어차피 CI 재현에 필요한 파일만 담는 쪽이 사본도 작고 의도도 분명했다.
→ **규칙: 디렉터리 사본을 뜰 때 블랙리스트(`--exclude`)가 아니라 화이트리스트로 간다.**

**docker 이미지 pull 시간**(`rhysd/actionlint` 최초 1회)은 다음부터 캐시된다. 비용 아님.
