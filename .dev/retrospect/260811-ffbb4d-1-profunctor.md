# 회고 — Optics profunctor 전환 (260811-ffbb4d · 회차 1, 작업 종료)

완료 조건 10개 전부 충족. 직전 작업에서 깨져 있던 **합성 `review`** 가 구조에서 나오게 됐다.

## 1. 무엇이 통했나

**사용자가 내 판단을 의심했고, 그게 맞았다.** 나는 "profunctor 전환은 Traversal 의 Wander
때문에 난이도가 높다" 고 했는데, 사용자가 "왜 높은지 이해 불가" 라고 되물었다.
다시 따져보니 **근거 없이 Haskell 의 사정을 JS 에 옮긴 것**이었다:

| | Haskell | JS |
| --- | --- | --- |
| `Wander` 의 어려움 | rank-2 타입(`forall f. Applicative f => ...`)을 타입 시스템이 강제 | **딕셔너리를 값으로 넘기므로 그 제약이 없음** |
| 구현 | 타입클래스 인스턴스 + 언어 확장 | `wander: (traverse, p) => s => traverse(_Identity, ...)` 한 줄 |

게다가 `wander` 가 필요로 하는 van Laarhoven traversal 은 **이미 `Traversable.of(key).traverse`
로 있었다.** 위임하면 끝이었다.

**말로 반박하지 않고 프로토타입으로 결론냈다.** 스크래치패드 30줄로 합성 review·Iso·Lens 에
review 시 올바른 거부까지 전부 확인한 뒤에 답했다. 내 주장이 틀렸다는 것도 그 자리에서
드러났다. **설계 논쟁은 30줄 프로토타입이 30문장보다 빠르다.**

**제약을 문서가 아니라 구조에 넣었다.** 이전 방식은 심볼 프로퍼티를 심어두고 `review` 가
그것을 검사했다 — 수동이고, 합성이 잃었다. 지금은 `Tagged` 에 `first`/`wander` 가 **없다는
사실 자체**가 "Lens/Traversal 은 review 할 수 없다" 는 제약이다. 잊거나 우회할 수 없다.

**그 제약을 테스트로 지켰다.** `_PTagged` 에 `first` 를 넣어 Lens review 를 허용해봤더니
테스트가 잡았다. **제약이 구조에 있다고 끝이 아니라, 그 구조가 유지되는지도 테스트해야 한다.**

## 2. 무엇을 잘못 가정했다

**난이도를 근거 없이 추정했다.** 이게 이 회차의 핵심 실패다. "Wander 는 어렵다" 는 명제는
참이지만 **그 어려움의 원인(rank-2 타입)이 JS 에는 없다**는 것을 확인하지 않고 결론으로 썼다.
익숙한 언어의 난이도를 다른 언어에 그대로 옮긴 것이다.

→ **규칙: 난이도를 이유로 방향을 접을 때는 그 난이도의 원인을 대라.** 원인을 못 대면
   추정이지 판단이 아니다.

**타입 파라미터가 런타임 시그니처에 없어도 괜찮다고 생각했다.** `Optic<S, A>` 를
`(P) => (pab: any) => (s: S) => any` 로 쓰자 `A` 가 어디에도 없어 `over(lens, s => s.toUpper(), p)`
의 `s` 가 `unknown` 이 됐다. 팬텀 멤버로 앵커를 만들어 해결했다.
**타입 파라미터는 추론될 자리가 있어야 한다.**

## 3. 이 회차를 싸게 만들었을 것은

**직전 작업에서 `review` 를 "정직한 절충" 이라 부르며 넘어간 것이 비용이었다.**
그때 이미 "합성이 build 를 잃는다" 를 알 수 있었는데, 단일 Prism 만 테스트하고 넘어갔다.
사용자가 지적하고 나서야 합성 케이스를 재봤다.
→ **부분 구현을 "절충" 으로 부르지 마라.** 무엇이 안 되는지 정확히 재고 그것을 말해야 한다.
   "review 는 심볼로 우회했다" 가 아니라 "합성된 Prism 에서는 안 된다" 가 정확한 서술이다.

**하위 호환을 미리 물었으면** `_makeCompose(name, noun)` 매개변수화라는 불필요한 구조를
만들지 않았다. 이번에 걷어냈다. 버전이 `0.0.0` 이고 `private: true` 라는 사실이 이미
저장소에 있었는데 확인하지 않았다.

## 남은 것

- **`Iso`** — `dimap` 만 쓰면 되므로 2줄이다. 프로토타입에서 이미 동작을 확인했다.
  사용자가 요청한 범위(Prism + Traversal)를 넘어 넣지 않았다
- `Optional`, `Fold`, `Getter`/`Setter` — `composeOptic(lens, prism)` 이나 `toListOf` 로
  이미 되므로 타입 수준 구분이 목적일 때만 값어치가 있다
- `traversed` 가 쓸 수 있는 Traversable 이 array/maybe/either 셋뿐. Object/Map 이 필요하면
  `Traversable` 인스턴스를 먼저 추가해야 한다
- **타입 정밀도** — 지금 `Lens`/`Prism`/`Traversal` 이 TS 에서 같은 shape 다. 브랜드를 붙이면
  `review(lens, x)` 를 컴파일 타임에 막을 수 있다. 런타임은 이미 막는다
