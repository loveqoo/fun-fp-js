# docs 정비 회고 — 주석 30줄이 실행되는 예제 2블록이 됐다

작업 `260812-a866ff`. 리뷰어 2차 #6("새 레지스트리 표면 다섯이 docs 에 0건")만 처리.

## 무엇이 통했나

### 쓰기 전에 전부 실행했다 (규칙 24)

문서를 쓰기 전에 다섯 표면의 동작을 **먼저 돌렸다.** 그 출력으로 예제를 썼다.

앞 작업에서 「이름 규칙」 표를 쓸 때 숫자만 돌리고 의미를 안 물어 8개를 오분류했다.
이번엔 **주장 15개를 전부 실측과 대조**했다(전부 일치).

**문서 예제 검사기는 "예외 없이 끝나는지" 만 본다** — 주석의 `// 1` 같은 기대값은 안 본다.
그래서 기대값은 사람이 따로 대조해야 하고, 나는 그것을 검증 항목으로 넣었다.

### `plus(maybe)` vs `maybe(first)` 가 드디어 문서에 있다

이 구분을 설명하는 데 **`CLAUDE.md` 12줄 + `index.js` 17줄 = 주석 29줄**이 들었다
(앞 작업 리뷰 #10 이 "이름이 못 지는 짐을 주석이 진다" 고 지적한 그것).

이제 `docs/Monoid.md` 에 **실행되는 예제 2블록**으로 있다:

```
payload 타입이 같으면      → 둘 다 Just(1)
섞이면                    → plus(maybe): Just(1) / maybe(first): THROW
```

**예제가 곧 회귀 테스트다** — `docs/*.md` 는 전부 실행 검사를 받으므로, 둘의 관계가 바뀌면
빌드가 빨개진다. 주석은 그렇게 안 된다.

### 규칙 28 을 지켰다

앞선 리뷰가 *"검토 중 `index.js` 가 네 번 바뀌었다"* 로 리포트를 시작했다. 이번엔 리뷰어
프롬프트에 "네가 도는 동안 아무것도 안 고친다" 를 명시하고 실제로 지켰다 — Compounding 의
회고도 `.dev/` 에만 쓴다.

### 문서를 쓰다 구조가 보였다

`docs/README.md` 에 「레지스트리 키」 표를 만들면서 **매개변수화 키가 6종**이라는 것이
처음으로 한 자리에 모였다:

```
<타입> · <클래스이름> · maybe(<inner>) · plus(<타입>) · const(<monoid>) · statet(<M>)
```

**흩어져 있을 때는 "규칙이 있다" 는 것 자체가 안 보였다.** `maybe-first` 같은 하이픈 이름을
만든 것도 이 표가 없었기 때문이다.

## 이 회차를 싸게 만들었을 것

### 「레지스트리 키」 표를 훨씬 전에 만들었어야 했다

`maybe-first` 를 만든 회차, `plus(maybe)` 이름을 정한 회차, `const(<키>)` 를 정한 회차 —
**세 번 다 이 표가 있었으면 5초 만에 답이 나왔다.** `CLAUDE.md` 「이름 규칙」 절에
레지스트리 키 형식을 넣은 것이 앞 작업이고, 사용자용 문서에는 이번에야 들어갔다.
