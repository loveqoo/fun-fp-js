# 회고 — 테스트 게이트 복구 (260805-02c344 · 회차 1)

작업: `npm test` 단일 진입점 도입 + 실행조차 되지 않던 `tests/unit-validation.test.js` 수리.
완료 조건 6개 전부 충족.

## 1. 무엇이 통했나

**"통과하는가"가 아니라 "실패할 때 실패하는가"를 완료 조건에 박아둔 것.**
조건 3번(`의도적으로 실패하는 임시 테스트를 넣었을 때 non-zero 로 종료함을 실제로 확인`)이
없었다면 러너를 만들고 초록불을 보고 끝냈을 것이다. 실제로는 4가지 실패 유형
(assertion 실패 / import 크래시 / 타입 에러 / SIGKILL)을 하나씩 주입해봤고, 전부 잡혔다.
**게이트를 만드는 작업의 완료 조건은 반드시 실패 주입을 포함해야 한다.**

**적대적 검토를 액면 그대로 받지 않고 재현한 것.**
codex 가 "floating `testAsync` 가 통째로 구멍"이라고 보고했다. 그대로 믿었으면 과잉 수정을
했을 것이고, 무시했으면 진짜 구멍을 놓쳤을 것이다. 3가지 케이스를 스크래치패드에서 직접
돌려보니 결론이 갈렸다:

| 케이스 | 수정 전 |
| --- | --- |
| 타이머 뒤 실패 | exit 1 — 잡힘 |
| 마이크로태스크 뒤 실패 | exit 1 — 잡힘 |
| settle 되지 않는 promise | **exit 0 — 조용히 통과** |

즉 보고는 과장이었지만 **핵심에는 진짜 결함이 있었다.** 재현이 두 오류를 동시에 막았다.

**계획 전에 미지수를 스크래치패드에서 먼저 없앤 것.**
`unit-validation.test.js` 는 288줄이고 한 번도 실행된 적이 없어서, 문법을 고쳐도 통과할지
몰랐다. 저장소를 건드리지 않고 스크래치패드에 ESM 사본을 만들어 돌려보니 23 assertion 전부
통과였다. 덕분에 계획에 "실패하면 어떻게 한다" 분기를 넣을 필요가 없어졌다.

## 2. 무엇을 잘못 가정했나

**"테스트가 다 통과한다"고 믿고 시작했다.** 실제로는 37개 중 1개가 몇 달간 실행조차 되지
않고 있었다. 초록불처럼 보이는 상태가 사실은 아무도 안 보고 있는 상태였다.

**문서에 적힌 명령이 동작한다고 가정했다.** `CLAUDE.md:25` 의 "전체 테스트" 명령
`node tests/*.test.js` 는 셸이 37개 경로로 확장하지만 **node 는 첫 인자만 실행하고 나머지는
`process.argv` 로 넘긴다.** 문서의 주 명령이 1/37 만 돌리고 있었다. 대체 명령으로 적힌 셸
루프도 실패를 집계하지 않아 exit code 가 항상 0이었다. **명령어 문서는 검증 대상이지 근거가
아니다.**

**`spawnSync` 타임아웃이면 hang 을 막을 수 있다고 잠깐 생각했다.** 틀렸다. settle 되지 않는
async 테스트는 이벤트 루프가 비어 **즉시** exit 0 으로 끝난다. 프로세스가 매달려 있지 않으므로
타임아웃이 걸릴 대상 자체가 없다. 해결은 러너 바깥 — `tests/utils.js` 에서 미결 테스트를
추적해 `process.on('exit')` 에서 실패시키는 것이었다.

## 3. 이 회차를 싸게 만들었을 것은

**단계별 쓰기 권한 표를 Planning 때 봤어야 했다.** Execution 에서 `CLAUDE.md` 를 편집하려다
`block/stage_write` 로 막혔다 (`CLAUDE.md` 는 context 클래스 — Context 단계에서만 쓸 수 있다).
완료 조건 6번이 처음부터 CLAUDE.md 수정을 요구하고 있었으므로, **Planning 에서 "이 계획이
건드릴 파일들의 쓰기 클래스"를 미리 확인했다면** `harness allow` 왕복 한 번이 없었다.
→ 계획에 "변경 대상 파일" 목록을 쓸 때 각 파일의 쓰기 클래스를 같이 적는다.

**셸 사용에서 3번 헛돌았다** (`ls`/`cat`/`cd` 실패 ×3). 원인은 두 가지였다:
zsh 에서 `*.d.ts` 같은 glob 이 매치되지 않으면 `no matches found` 로 **명령 전체가 죽고**
(bash 와 다르다), 그리고 `grep -n '...```...'` 처럼 백틱이 든 패턴을 큰따옴표로 감싸
`unmatched "` 가 났다.
→ zsh 에서 glob 이 빌 수 있으면 `ls foo* 2>/dev/null || true` 로 감싸고, 백틱·특수문자가 든
grep 패턴은 **작은따옴표**를 쓴다.

**`git checkout -- dist` 를 하기 전에 dist 를 재빌드해버렸다.** 동기화 확인이 목적이었는데
작업 트리를 오염시켰다. 결과적으로 타임스탬프만 다르다는 유용한 사실을 얻었고 즉시 복구했지만,
읽기 전용 확인은 `git stash` 없이도 되는 방식(빌드 산출물을 임시 경로로 뽑기)이 있었다.

## 후속 (이번 범위 밖)

- **`package.json` 에 `engines` 없음** — Node 15 미만에서는 unhandled rejection 이 프로세스를
  죽이지 않아 게이트에 구멍이 남는다. `"engines": {"node": ">=18"}` 권고. 지원 런타임 결정은
  프로젝트 정책이라 임의로 넣지 않았다.
- **dist 빌드 타임스탬프** — `dist/*` 4개 파일 헤더의 `Built: <ISO>` 때문에 내용이 같아도
  재빌드하면 항상 diff 가 난다. 커밋된 dist 가 소스와 일치하는지 기계적으로 검증할 수 없다.
  후보 문서 B항 (`.dev/plan/260805-02c344-1-candidates.md`).
- **CI 없음** (`.github/` 자체가 없다). 이제 `npm test` 라는 단일 진입점이 생겼으므로 CI 도입
  비용이 낮아졌다.
- **`tests/utils.js` 의 `assertThrows`** 가 에러 종류를 구분하지 않고 아무 예외나 통과시킨다.
