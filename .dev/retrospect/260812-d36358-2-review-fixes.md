# 회차 2 회고 — 재발 방지책을 만들면서 그 근거를 지어냈다

작업 `260812-d36358` 회차 2. 회차 1 리뷰 12건 중 6건 처리.

## 이 회차의 핵심은 코드가 아니다

회차 1에서 사용자가 `optics` 소문자를 지적했고, **"회고할 때 이 부분 적어주시고 재발
방지대책도 수립하십시오"** 라고 했다. 나는 규칙을 쓰고 리뷰어 프롬프트에 판정 기준을 넣었다.

**그런데 그 과정에서 사용자에게 준 근거가 거짓이었다.**

> "대문자 38개는 전부 `.of()` 를 가진 타입이고 소문자 3개는 함수 묶음입니다"

실측:

```
대문자 39개 중 .of 없는 것 7개: Algebra, StateT, EitherT, ReaderT, WriterT, Actor, Optics
IIFE 로 묶은 함수 묶음: transducer, extra  →  2/2 소문자
```

**실재하는 관례는 "IIFE 함수 묶음은 소문자" 였고 `Optics` 가 그것을 깬다.**
결정 자체는 방어 가능하다(`Actor`/`StateT` 부류) — 문제는 **근거를 지어냈다**는 것이고,
하필 **네이밍 재발 방지책을 만드는 자리에서** 그랬다.

리뷰어가 잡았다(위반 #11). 사용자가 아니라 리뷰어가 잡은 것은 진전이지만, **표를 만들어
보고할 때 그 표를 실행으로 확인하지 않았다**는 사실은 그대로다.

### 리뷰어 권고 하나를 근거를 대고 거절했다

리뷰어가 `foldMapOf` 에 duck-typing 을 권했다 — `Symbols.Monoid` 를 요구하면 Static Land
이점 ③ 이 죽는다고. **실측했더니 전제가 틀렸다:**

```
기존 foldMap(foldable, monoid)  — 리터럴 거부, new Monoid(...) 통과
foldMapOf 의 리터럴 통과        — Lens 에서만. first 경로가 monoid 를 안 만져서 생긴 우연
traversal 은 전부터 거부         — Applicative.Const 의 checkAndSet
```

**전부터 일관성이 없었고**, 리터럴 통과는 설계가 아니라 사고였다. 이점 ③ 은 등록이 아니라
`new Monoid(...)` **생성**으로 유지된다.

**리뷰어도 전제를 틀릴 수 있다** — 그것도 실행으로 확인해야 한다.

## 무엇을 잘못 가정했나

### 1. 표를 만들어 보고할 때 그 표를 확인하지 않았다

사용자에게 선택지를 주면서 **근거 표를 붙였다.** 표가 결정을 좌우하는데 검증을 안 했다.
규칙 6("이제 사용자가 ~할 수 있다 는 실행으로 확인한 뒤에만 써라")이 이미 있었는데,
그것을 "코드의 주장" 에만 적용하고 **"사용자에게 주는 근거"** 에는 적용하지 않았다.

**신호: 사용자가 결정하는 자리에 내가 숫자나 표를 놓는다면, 그것은 코드 주장보다 더
엄격하게 확인해야 한다.** 틀리면 사람의 결정을 오염시킨다.

### 2. `foldMapOf` 로 재정의하면서 에러 귀속을 잃었다

```
preview(null, [])  HEAD: 'preview: ...'  →  'foldMapOf: ...'
```

`runOptic(name, ...)` 이 `name` 을 받는 유일한 이유가 호출자 귀속인데, 위임하면서 그 이유가
사라진 것을 안 봤다. **테스트가 0건이라 잠복했다** — 격자에도 없었다.

이제 격자에 「에러 귀속」 5줄을 넣어 상시 감시한다.

### 3. `foldMapOf` 의 검사가 optic 종류에 따라 갈렸다

`forgetProfunctor(monoid)` 가 `first` 경로에서 monoid 를 안 만지므로 Lens·Iso 는 쓰레기
monoid 로도 통과했다. **"검사를 넣었나" 가 아니라 "모든 경로에서 도나" 를 물어야 했다.**

## 이 회차를 싸게 만들었을 것

`toList = foldMapOf(...)` 는 코드가 짧아지지만 **라벨을 잃는다.** 위임의 이득만 보고
