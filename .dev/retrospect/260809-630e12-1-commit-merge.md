# 회고 — 커밋 및 main 머지 (260809-630e12 · 회차 1, **미완료 — 회차 2 필요**)

완료 조건 7개 중 **5개 충족**. 6·7(`origin/main` push, GitHub CI 실행)은 **외부 요인으로
막혔다** — PAT 에 Workflows 권한이 없어 `.github/workflows/ci.yml` 을 push 할 수 없다.

## 1. 무엇이 통했나

**커밋 분할을 파일 목록이 아니라 실행으로 검증했다.** 완료 조건 2는 "각 커밋이 해당 작업의
파일만 담고 있으며 `git show --stat` 으로 확인했다" 였는데, 그것만으로는 **커밋이 독립적으로
동작하는지** 알 수 없다. 네 커밋을 각각 `git worktree` 로 체크아웃해 `npm test` 를 돌렸고
전부 exit 0 이었다. 이제 `git revert` 나 `git bisect` 가 중간 상태에서 깨지지 않는다는 것을
안다. **"파일이 맞게 들어갔나" 와 "그 커밋이 동작하나" 는 다른 질문이다.**

`node_modules` 는 워크트리에 심볼릭 링크로 붙여 재설치 없이 돌렸다.

**공유 파일의 분할 비용을 다르게 판단했다.** `package.json` 은 `test` 스크립트(작업 1)와
`engines`(작업 2)가 섞여 있어 임시 편집 한 번으로 나눴다 — `engines` 는 CI 의 산출물이므로
나눌 값어치가 있었다. 반면 `CLAUDE.md` 는 세 작업의 갱신이 모두 들어 있었지만 **나누지
않았다.** 세 번의 파일 수술을 반복할 값어치가 없고, 프로젝트 가이드는 세션 단위로 한 번
갱신되는 편이 이력상 자연스럽다. **원자성은 목적이 아니라 수단이다** — 되돌릴 수 있어야
하는 것(코드·설정)과 그렇지 않은 것(가이드 문서)을 구분했다.

## 2. 무엇을 잘못 가정했나

**push 가 성공할 것이라 가정했다.** 커밋·머지·테스트를 다 끝내고 마지막에야 막혔다.
원인은 코드가 아니라 자격증명이었다 — `GITHUB_TOKEN` 환경변수로 주입된 fine-grained PAT 에
Workflows 권한이 없다. **워크플로 파일을 처음 추가하는 커밋은 일반 push 와 권한 요구가
다르다.** CI 를 도입한 회차(260809-31bb80)에서 이 점을 미리 확인했어야 했다.

곁가지로 확인한 것: SSH 키는 로컬에 있지만 GitHub 에 등록돼 있지 않다
(`Permission denied (publickey)`). 대체 경로도 즉시 쓸 수 없었다.

**`gh auth refresh` 로 고칠 수 있을 것이라 잠깐 생각했다.** 토큰이 환경변수로 주입되면
`gh` 가 바꿀 수 없다. 확인하고 알았다.

## 3. 이 회차를 싸게 만들었을 것은

**`.github/` 를 처음 커밋하기 전에 push 권한을 확인했어야 했다.** CI 도입 회차의 회고에
"CI 는 아직 GitHub 에서 돌지 않았다" 를 적어뒀으면서도, 그 첫 실행을 막을 수 있는 것이
무엇인지는 점검하지 않았다. **원격에 처음 나가는 종류의 파일(workflow, GitHub App 설정 등)은
로컬 검증이 끝난 시점이 아니라 시작 시점에 권한을 확인한다.**
→ 확인 방법: `gh auth status` 의 스코프, 또는 빈 커밋으로 dry-run push.

**`.claude/harness` 가드를 또 밟았다.** `git add -n .claude/harness/` 같은 **읽기 전용
dry-run 도 차단된다** — 가드는 의도가 아니라 인자 문자열을 본다. 이미 회고 규칙 4번에
"블랙리스트가 아니라 화이트리스트" 로 적어뒀는데, 이번엔 경로를 **직접 지정하는** 형태여서
같은 함정의 다른 얼굴이었다. 해법은 `git add -A` (경로 미지정)였고, `.gitignore` 가
`bin/` 과 `harness.db*` 를 이미 제외하므로 결과도 정확했다.
→ **규칙 보강: `.claude/harness` 는 인자에 넣지 마라. 경로를 지정하는 대신 전체 대상
   명령(`git add -A`)을 쓰고 `.gitignore` 에 맡긴다.**

**`git status --cached` 는 없는 옵션이다** (`--porcelain` 이나 `git diff --cached --stat`).
사소하지만 왕복 한 번을 썼다.
