# 회고 — 기존 30종 문서 편입 (260809-4aef61 · 회차 1/2)

조건 8개 중 5개 충족. 조건 3(실패 0건)은 수리 대기 55건이 남아 회차 2로 넘긴다.

## 1. 무엇이 통했나

**문서를 고치기 전에 도구를 의심했다.** 처음 측정에서 307개 중 53개(17%)만 통과했다.
254개를 손으로 고칠 뻔했는데, 실패 원인을 보니 `ReferenceError: Maybe is not defined` 가
90건 넘었다 — 기존 문서가 한 블록에서 `const { Maybe } = FunFP;` 하고 이후 블록에서 맨이름을
쓰기 때문이었다. **프리앰블을 바꾸자 문서를 한 글자도 안 고치고 17% → 51%** 가 됐다.

핵심은 `const` 선언이 아니라 **`Object.assign(globalThis, FunFP)`** 여야 한다는 것.
예제가 스스로 `const { Maybe } = FunFP;` 를 하는 경우가 많아 `const Maybe` 를 주입하면
`Identifier 'Maybe' has already been declared` 가 난다.

같은 판단을 한 번 더 했다 — 블록 첫 줄의 `import FunFP from 'fun-fp-js';` 가 프리앰블과
충돌해 26건이 깨졌는데, **그 줄은 독자에게 유용하므로 문서에서 지우지 않고 검사기가
걷어내게** 했다. 136 → 116.

**대량 실패 앞에서 "문서가 잘못됐다" 로 결론내지 마라. 도구의 전제를 먼저 의심하라.**

**문서가 존재하지 않는 API 를 설명하고 있었다.** 이 작업이 찾으려던 부패가 실제로 나왔다:

| 문서 | 잘못 | 실제 |
| --- | --- | --- |
| `Foldable.md` ×5 | `Monoid.of('sum')` | `'number'` (empty 0, concat 덧셈) |
| `Setoid.md` ×2 | `Setoid.of('array'\|'object')` | 미제공 — 커스텀 Setoid 필요 |
| `Monoid.md` | `Monoid.of('object')` | 미제공 — 커스텀 Monoid 필요 |

사용자 판단에 따라 라이브러리에 기능을 추가하지 않고 **문서를 실제 API 에 맞췄다.**
커스텀 인스턴스 만드는 법을 보여주는 쪽이 오히려 문서로서 낫다.

**`no-run` 에 이유를 강제한 것.** 이게 없으면 `no-run` 이 만능 도피처가 된다. 펜스 정보
문자열에 이유를 적게 하고 없으면 실패시켰다 — 기계적으로 강제된다. 실제로 **내가 먼저
걸렸다**: 신규 7종에 이유 없이 `no-run` 을 달아뒀던 것이 7건 실패로 잡혔다.

**빨간 CI 로 회차를 끝내지 않았다.** 계획에 미리 적어둔 규칙이다. 55건이 남았지만
`PENDING` 목록으로 분리해 CI 를 초록으로 유지했다. 눈속임이 되지 않도록 **매 실행마다
개수를 출력**한다(`수리 대기: 문서 24개 / 실패 55건`). 목록은 줄기만 하고, 0이 되면 지운다.

## 2. 무엇을 잘못 가정했나

**완료 조건 3(85%)이 도달 불가능이었다.** 조건을 정할 때 307개 전부가 "실행 가능한 예제"
라고 가정했는데, 실제로는 **52개가 대수 법칙·시그니처 표기**였다:

```
Alt.alt(a, b): Alt a        ← 시그니처
equals(a, a) === true       ← Setoid 법칙, a 는 자유변수
concat(a, empty) === a      ← Monoid 법칙
```

전부 고쳐도 천장이 260/312 = **83.3%**. 사용자와 합의해 조건을 **"실패 0건"** 으로 바꿨다.
비율보다 이쪽이 실질 목표(CI 초록)와 일치한다.

→ **교훈: 코퍼스의 성격을 모르는 상태에서 비율 목표를 세우지 마라.** 조건을 정하기 전에
   표본을 열어봤다면 시그니처·법칙 블록의 존재를 알았을 것이다.

**자동 수리 스크립트가 새 실패를 만들었다.** 선언을 블록 앞에 붙이는 스크립트가
여러 줄짜리 `const objectMonoid = new Monoid(` 를 한 줄로 잘라 붙여 `Monoid.md` 에
새 실패를 냈다. **생성 스크립트의 결과도 검증해야 한다** — 다행히 검사기가 잡았다.

## 3. 이 회차를 싸게 만들었을 것은

**Selection 에서 표본을 열어봤다면** 조건 3을 처음부터 옳게 세웠고, 중간에 조건을 바꾸는
왕복(측정 → 불가능 확인 → 사용자 합의 → `--clear` → 재기록)이 없었다.
비용은 실측 몇 번이었다.

**`harness allow` 를 Execution 시작 시점에 받았어야 했다.** `docs/*` 쓰기 예외를 안 받고
python 스크립트로 문서를 고치려다 차단됐다. 직전 회고의 규칙 2(쓰기 클래스 선확인)를
파일 편집에는 적용했으면서 **스크립트를 통한 편집**에는 적용하지 않았다.
