### 회차 3에서 만든 규칙이 회차 4에서 즉시 값을 냈다

규칙 25 — **"선례를 따를 때는 그 이름으로 파일 전체를 grep 해 구성 요소를 목록으로 대조하라"**.

그리고 규칙이 말한 두 번째("완료 조건에 '선례와 동일하게 동작한다' 를 넣어라")를 이번

```
Monoid.of("maybe(first)")       => OK, 캐시 동일: true

키를 미리 만들지 않는다: true      ← 지연 해석이지 사전 등록이 아니다
```

조건을 "동작하는가" 로만 썼으면 캐시 동일성과 사전 등록 여부는 안 봤을 것이다.

같은 파일 앞쪽 테스트가 `Applicative.Const('array')` 를 부르면 키가 이미 등록돼
**resolver 없이도 통과한다.** 계획서에 그 사실을 적고 아무도 안 쓰는 `'string'` 키를 골랐다.

```
grep -c "Applicative.Const('string')" tests/*.js  →  전부 0
뮤테이션(resolver 제거) → 2건 빨간불
```

**키를 잘못 골랐으면 0건이었다** — 규칙 15("어서션을 쓰는 순간 변경 전에도 통과하나 물어라")의
