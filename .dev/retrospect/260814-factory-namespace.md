# 회고 — 규칙이 둘인 것을 발견하고도 소유자에게 고르라고 넘겼다

**2026-08-14.** 인스턴스 팩토리가 `Maybe.Semigroup` 6개와 `Setoid.Array` 5개로 갈려
있었습니다. 발견한 것은 제가 맞지만, **거기서 멈춰서 "어디까지 통일할까요" 라고 물었습니다.**

소유자 판정 — *"두 가지라고 저에게 이야기하지 않았습니다. 우선 그게 명확한 위반이고요,
그래서 이 지경까지 온 겁니다. 함수형 라이브러리는 애매하게 만들면 망한 겁니다. 명확하게
방향을 잡고 구현할 책임이 있어요."*

## 무엇이 실패인가

**질문이 실패입니다.** 5:6 이면 어느 쪽도 예외가 아니고, 그건 취향 문제가 아니라
**결함 보고**입니다. 그런데 저는 그것을 선택지로 만들어 넘겼습니다.

선택지를 만들어 주면 "고르는 일" 이 되고, 고르는 일이 되면 **근거를 대는 책임이
사라집니다.** 실제로 근거는 코드 안에 이미 있었습니다 —

- `tests/registry-api.test.js` 가 원래부터 "타입 클래스는 인스턴스, 데이터 타입은 값" 을
  지키고 있었습니다. 팩토리는 인스턴스를 냅니다. **답은 이미 정해져 있었습니다.**
- `Semigroup.Maybe('array')` 는 `Semigroup<Maybe<Array>>` 로 읽힙니다. 뒤집으면
  `Maybe<Semigroup<Array>>` 인데 **그런 값은 존재하지 않습니다.** 소유자가 이 질문을
  직접 던져서야 제가 이 근거를 말했습니다.

두 근거 다 제가 찾을 수 있었고, 찾았다면 물을 일이 아니었습니다.

## 규칙 94 의 재발이다

*"틀 안에서 최적화하기 전에 틀을 세어 보라. 'A냐 B냐' 를 물으면 '둘 다 아니다' 가
답지에서 사라진다."* — `dist/` 때 적은 것입니다. 이번엔 답지에서 사라진 것이
**"둘 다 아니다"** 가 아니라 **"이건 물을 일이 아니다"** 였습니다.

## 같이 드러난 것

`Semigroup.Either` 의 타입 선언이 인자 **하나**인데 런타임은 **둘**을 요구했습니다.
TypeScript 로 쓰면 통과하고 실행하면 던지는 상태였습니다. 개명하면서 게이트에 사례표를
넣다가 걸렸습니다 — **표를 만들면 걸린다**(규칙 93)의 또 다른 사례입니다.
